How we work

작업의 흐름

목표에 따라 팀장이 팀을 편성하고, 산출물을 다음 팀원에게 넘기며, 마지막에 검토 게이트를 통과시킵니다.

새 제품 (0 → 1)

기획 단계가 앞에 붙습니다
  1. 사업개발(BD) — 시장·경쟁·수익으로 착수 판정
  2. 프로덕트 매니저 — PRD 앞부분(범위·성공 기준)
  3. 브랜드 디자이너 — 아이덴티티·톤 (PD보다 먼저)
  4. 프로덕트 디자이너 — 화면·상태·디자인 시스템
  5. 팀장 → 앱·백엔드 — 구현 → QA 게이트 → 릴리즈

기존 제품의 기능 추가 (1 → n)

사업성·브랜드가 있으면 건너뜁니다
  1. 프로덕트 매니저 — 범위·완료 기준
  2. 프로덕트 디자이너 — 화면·카피
  3. 앱 + 백엔드 — 인터페이스 계약을 먼저 합의
  4. QA — 검증 게이트 (통과 전 커밋 금지)
  5. 릴리즈 매니저 — 배포 경로 판정 (OTA/빌드)
01
결정마다 주인은 한 명

역할마다 주 산출물(DRI) 한 줄. 기록자도 팀장 하나.

02
결정은 회의가 아니라 문서로

BUSINESS_CASE · PRD · BRAND · DECISIONS. 대화로 넘긴 건 사라집니다.

03
고객에서 거꾸로 쓴다

BD는 보도자료 한 문단부터, PD는 여정 프레임부터.

04
시간 고정, 범위를 자른다

감당할 크기(appetite)를 먼저 적고, 넘치면 다시 자릅니다.

05
비평은 있고 지시는 없다

에스컬레이션은 늘 2~3안 + 트레이드오프.

06
단계적으로 노출한다

테스터 → 실기기 → 실사용자. 되돌릴 경로를 발행 전에 정합니다.
