---
description: 세션 마감 — 검증, HARNESS 갱신, 커밋까지
---

이 세션을 마감한다. 다음을 빠짐없이 수행하라:

1. **검증 게이트**: 프로젝트 verify를 돌리고 **종료코드로** 판정한다
   (`> log 2>&1; [ $? -eq 0 ]` 꼴). 번들·네이티브를 건드렸으면 export 검증까지.
   실패하면 마감하지 않는다 — 고치거나, 못 고치면 실패 상태를 그대로 기록한다.
2. **HARNESS 갱신** (`docs/HARNESS.md`):
   - "지금 상태"를 오늘 작업 결과로 고친다 — 완료(✅)·주의(⚠️)·대기(🔒)를 구분해서.
   - **"다음 세션이 챙길 것"을 ① ② ③으로 명시한다** — 사람 손이 필요한 일(PO 몫)과
     에이전트 몫을 구분한다.
   - 새로 배운 규칙(사고가 있었다면)을 "고치기 전에 확인할 규칙" 표에 추가한다.
   - 해결된 옛 항목은 지우지 말고 "✅ 해결됨 (날짜)"로 강등한다.
3. **PO 결정이 있었으면** `docs/DECISIONS.md`에 번호를 붙여 기록하고 HARNESS
   요약표를 갱신한다.
4. **커밋·푸시**: 트리를 클린으로 만들고 원격과 동기화한다. 커밋 메시지는 다음
   세션이 `git log`만 보고도 흐름을 알 수 있게 쓴다.
5. 마지막 보고: 완료한 것 / 검증 결과 / 다음 세션·PO가 할 일을 요약한다.

거짓 마감 금지: 검증 없이 "됐습니다"라고 쓰지 않는다. 문서가 코드보다 앞서 있으면
거짓말이다.
