---
description: 새 기능/작업 시작 절차 — 상태 점검부터 PRD 위임까지
---

새 작업을 시작한다. 다음 순서로 진행하라:

1. `docs/HARNESS.md`를 읽고 "지금 상태"와 "다음 세션이 챙길 것"을 확인한다.
2. `git log --oneline -20`으로 다른 툴이 쌓은 커밋을 확인하고,
   `git fetch origin && git checkout -b <작업브랜치> origin/main`으로 시작한다.
3. PO의 요청($ARGUMENTS)을 확인하고 **새 제품인지 기존 제품의 기능인지** 가른다
   (TEAM.md §3 기능 사이클).
   - **새 제품(0→1)**: BD(`.claude/agents/bd.md`) → 착수 판정. PO 판정 후
     PM(`pm.md`) → PRD 앞부분, BRAND(`brand.md`) → 브랜드, PD(`pd.md`) → 디자인 섹션.
     **PM→PD, BRAND→PD는 순차다** (같은 파일·파생 관계).
   - **기존 제품의 기능(1→n)**: BD·BRAND를 건너뛴다. PM → PRD, PD → 화면·카피.
   - 요금제·게이트에 영향이 있으면 기능 카탈로그에 키부터 추가한다.
   - **필요한 역할만 부른다.** 역할이 9개라고 9번 위임하지 않는다.
4. PRD가 나오면 PO 승인을 받은 뒤 작업을 분해한다:
   - APP/BE가 같은 파일을 건드리지 않으면 병렬, 겹치면 순차.
   - 인터페이스 계약(스키마·엔드포인트)을 먼저 문서로 합의시킨다.
5. 각 위임 프롬프트에 반드시 포함: 역할 하네스 경로, 이번 작업의 입력과 기대
   산출물, 건드리면 안 되는 것.

비가역 행동(배포·제출·삭제·과금·대외 발행)은 PO 승인 전에 실행하지 않는다.
