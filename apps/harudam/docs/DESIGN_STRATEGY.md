# 디자인 전략 — 하루담 (가제)

작성: **PD** · 2026-09-02 · 상태: **PO/BRAND 확정 대기** (색·톤·이름 원본은 `BRAND.md` 소유)

이 문서는 `PRD.md` §4·§5·§9(화면·문구)의 **밑바탕**이다. 화면이 "무엇을 말하는가"는
PRD가, "무엇으로 그려지는가"(토큰·컴포넌트·접근성·반응형·스토어 레이아웃)는 여기가
정한다. **색·타이포·톤의 원본은 `BRAND.md`이고 이 문서는 파생이다** — 여기서 색을
새로 만들면 브랜드는 없는 것이다 (TEAM.md 규칙 8, PD 하네스). 브랜드에 없는 값이
필요하면 "BRAND에 물을 것"으로 남긴다.

> **파생 관계 한눈에**
> - 색 16토큰 × 라이트/다크 → `BRAND.md` §6-2 (대비 검증표 포함) — **그대로 옮긴다**
> - 타이포 스케일 → `BRAND.md` §6-3 (부모 20px+·질문 28px+·마루 부리/Pretendard)
> - 모션 값 → `BRAND.md` §6-6 (300~450ms·숨 쉬는 원 4초·reduce-motion)
> - 터치·시니어 환경 → `BRAND.md` §2-2 (56px+·스와이프 금지·확대 200%)
> - **간격·radius·그림자·아이콘 규격**은 브랜드가 원본을 두지 않은 영역 →
>   PD가 이 문서에서 정한다(브랜드 성격 "단정한·느긋한"과 정합하도록 파생).

## 0. 두 밀도 — 하나의 브랜드, 다른 크기

`BRAND.md` §2가 못 박은 대로 결제자(자녀)와 사용자(부모)는 다르다. 브랜드는 하나지만
**같은 옷을 다른 크기로** 입는다. 이 문서의 모든 토큰·컴포넌트는 **두 밀도**를 가진다.

| | **부모 밀도** (앱, 60~70대) | **자녀 밀도** (웹, 40~50대) |
|---|---|---|
| 원칙 | 화면당 한 가지·큰 글씨·틀릴 수 없음 | 정보 있어도 됨·품격·"잘 샀다" |
| 본문 최소 | **20px** (기본 22px) | 17px |
| 터치 타깃 | **56px+** | 44px+ |
| 색 사용 | 색만으로 정보 전달 금지(문장·아이콘 동반), 감빛 버튼 화면당 1개 | 동일 원칙, 감빛 버튼은 주요 CTA에 |
| 오류 표기 | **문장만**(코드 노출 금지) | 문장 + **원인 코드**(로그 대조용) |
| 모션 | 최소·느림, 진동 녹음 시작/끝 각 1회 | 표준 |

이 표가 이후 모든 컴포넌트 규칙에서 "부모용/자녀용" 두 칸으로 반복된다.

## 1. 디자인 원칙 5개

> 형용사가 아니라 **화면에서 검사 가능한 규칙**이다. `BRAND.md` §1-3 성격 4개
> (다정한·느긋한·단정한·오늘의)에서 화면 층위로 파생시켰다.

| # | 원칙 | 뜻 | 화면에서 이렇게 검사한다 |
|---|---|---|---|
| **DP1** | **화면당 한 가지** | 부모 화면은 지금 할 일이 **하나**고, 그것이 3분이며, 틀릴 방법이 없다 | 부모 화면에 주요 동작(감빛 버튼)은 **하나**. 두 번째 선택지는 시트/다음 화면으로 민다. 자동 스크롤·자동 넘김 없음 |
| **DP2** | **통화의 은유, 앱의 부담 없이** | 부모에게는 "앱을 쓴다"가 아니라 "저녁에 누가 물어봐서 말한다"여야 한다 | 인터뷰 화면은 전체 화면·주소창 없음·**숨 쉬는 원** 하나·"말하기" 글자 버튼. 마이크 아이콘 단독 금지 |
| **DP3** | **안심이 먼저다** | "이거 딸이 다 봐?"(프라이버시)와 "내가 틀렸나?"(실수)가 부모 이탈의 두 축 | 동의 전 녹음 없음 · 실수해도 되돌릴 수 있음(스와이프에 기능 안 걸기) · "나만 보기"가 항상 한 손에 · 오류는 **부모 탓 문장 금지** |
| **DP4** | **느긋함이 곧 접근성** | 서두르지 않는 것이 시니어 배려의 본체다. 큰 글씨는 큰 크기지 유아적 장식이 아니다 | 애니메이션 300~450ms·튕김 없음 · 침묵 4초 대기 · 재촉·연속 기록·게임화 금지 · 큰 글씨는 **같은 서체의 큰 크기**(색을 유치하게 바꾸지 않음) |
| **DP5** | **브랜드가 물러서고 사람의 문장이 앞에 선다** | 선물 개봉에선 로고보다 자녀의 편지가, 리포트에선 우리 카피보다 **부모의 발췌**가 먼저다 | 선물 카드 첫 화면은 자녀 문장이 헤드라인 · 리포트는 부모 발췌를 큰따옴표로 원문 그대로(사투리 보존) · 우리는 수식하지 않는다 |

## 2. 디자인 시스템 토큰

### 2-1. 색 토큰 — `BRAND.md` §6-2에서 그대로 파생 (새 값 없음)

CSS 커스텀 프로퍼티 이름은 PD가 정하되 **값은 브랜드 표를 옮긴 것**이다. 값을
바꾸면 `BRAND.md` §6-2 대비 검증표를 다시 계산해야 하고, 그것은 BRAND의 승인이
필요하다(색 원본은 BRAND 소유). 라이트를 `:root`에, 다크를 `[data-theme="dark"]`와
`prefers-color-scheme: dark`에 둔다.

| CSS 변수 | BRAND 토큰 | 라이트 | 다크 | 용도 |
|---|---|---|---|---|
| `--bg` | bg (한지) | `#FAF6EE` | `#1E1A17` | 화면 바탕. 순검정/순백 금지 |
| `--surface` | surface | `#FFFFFF` | `#2A2521` | 카드·시트 |
| `--ink` | ink (먹) | `#2B2723` | `#F2ECE2` | **부모 본문은 반드시 이 색.** 회색 본문 금지 |
| `--ink-2` | ink-2 | `#5A534B` | `#C8BFB3` | 보조 본문 |
| `--muted` | muted | `#6E665D` | `#A79D91` | 캡션·날짜 (4.5:1 유지) |
| `--line` | line | `#D9D2C7` | `#3F3831` | 장식 구분선 (정보 전달용 아님) |
| `--line-strong` | line-strong | `#847B71` | `#7C7267` | 입력 테두리·아이콘 선 (비텍스트 3:1) |
| `--primary` | primary (감빛) | `#B5471F` | `#E98A5E` | **유일한 행동 색. 화면당 버튼 하나** |
| `--primary-hover` | primary-hover | `#9C3A16` | `#F2A27E` | 눌림 |
| `--on-primary` | on-primary | `#FFFFFF` | `#1E1A17` | 버튼 글자 |
| `--primary-soft` | primary-soft | `#F6E3D9` | `#3D2A22` | 배지·강조 배경 (위에 `--ink`) |
| `--accent` | accent (쑥빛) | `#4E6B4A` | `#9DBB8F` | 완료·성장 (초록 남발 금지) |
| `--accent-soft` | accent-soft | `#E3EBDD` | `#2F3A2C` | 쑥빛 연한 면 |
| `--warn` | warn | `#8A5A00` | `#E0B25C` | 주의 |
| `--error` | error | `#A6321E` | `#F08B7A` | **자녀 화면·로그 전용.** 부모 화면은 색이 아니라 문장 |
| `--focus` | focus | `#1F5FA8` | `#8FBBF0` | 키보드 포커스 링 (유일한 파랑, 접근성 전용) |

**색 사용 규칙 3가지 (BRAND §6-2 그대로):**
1. 부모 화면에서 **색으로만** 정보를 전달하지 않는다 — 문장·아이콘을 동반한다.
2. 감빛(`--primary`) 버튼은 **화면당 하나**.
3. 그라데이션·네온·반투명 유리 효과 없음.

**부모 화면에 `--error`(빨강)를 칠하지 않는다.** 부모에게 오류는 색이 아니라
"잘 못 들었어요" 같은 문장이다(BRAND §5-2, 팀 규칙 6). 빨강은 자녀 화면·로그에만.

### 2-2. 타이포 토큰 — `BRAND.md` §6-3에서 파생

**서체**(원본 BRAND §6-3): UI·본문·버튼 = **Pretendard** Variable (SIL OFL) ·
제목·로고·책 본문 = **마루 부리** (SIL OFL). 손글씨·붓글씨·둥근 고딕·300 이하 웨이트
쓰지 않는다.

```
--font-ui:    "Pretendard Variable", Pretendard, system-ui, -apple-system, sans-serif;
--font-title: "MaruBuri", "Pretendard Variable", serif;   /* 제목·랜딩 헤드라인·책 */
```

**스케일** — 부모/자녀 두 밀도. 부모 값은 브랜드 최소치(20px+)를 하한으로 삼는다.

| 토큰 | 부모 앱 (px / weight / line-height) | 자녀 웹 | 근거 |
|---|---|---|---|
| `--fs-question` | **28 / 600 / 1.5** (인터뷰 질문) | — | BRAND §6-3 "질문 28px+" |
| `--fs-title` | 24 / 600 / 1.4 (마루 부리) | 32 / 600 / 1.25 (마루 부리) | 랜딩 헤드라인 32px+ |
| `--fs-body` | **22 / 500 / 1.6** (기본 본문) | 17 / 400 / 1.65 | 부모 20px 하한, 기본 22 |
| `--fs-body-min` | 20 / 500 / 1.6 (밀도 높은 곳 하한) | 15 / 400 / 1.6 | 부모 **절대 하한 20px** |
| `--fs-button` | **22 / 600** | 16 / 600 | BRAND "버튼 글자 22px 600" |
| `--fs-caption` | 18 / 500 / 1.5 (`--muted`) | 14 / 400 / 1.5 | 캡션도 부모가 읽는다 → 4.5:1 |

- 부모 앱: **시스템 글자 크기 확대 200%까지 레이아웃 유지**(BRAND §2-2). 고정 높이
  금지, `min-height` + 줄바꿈 허용.
- 굵기는 500 이상(부모), 얇은 웨이트로 대비를 떨어뜨리지 않는다.

### 2-3. 간격 · radius · 그림자 — PD 파생 (브랜드에 원본 없음)

브랜드 성격 "단정한·느긋한"(넉넉한 여백·모난 데 없는 부드러움, 그러나 장식 없음)에서
파생한 값이다. 4px 그리드. **이 세 항목은 색·타이포와 달리 브랜드 소유가 아니므로
PD가 정하고 BRAND에 되묻지 않는다**(PD 하네스 = 디자인 시스템 DRI).

```
간격:  --sp-1:4  --sp-2:8  --sp-3:12  --sp-4:16  --sp-5:24  --sp-6:32  --sp-8:48  --sp-10:64
```

| 용도 | 부모 | 자녀 |
|---|---|---|
| 화면 좌우 여백 | 24px | 20~24px |
| 카드 내부 패딩 | 24px | 16~20px |
| 요소 세로 간격(문단) | 24px | 16px |
| 주요 동작 위 여백(엄지 도달) | **하단 안전영역 + 24px** | 표준 |

```
radius:  --r-sm:10  --r-md:16  --r-lg:22  --r-pill:999   /* 모난 각·완전 원형 버튼 지양, 부드럽되 단정 */
그림자:  --shadow-card: 0 1px 2px rgba(43,39,35,.06), 0 8px 24px rgba(43,39,35,.05)   /* 낮고 부드럽게. 광택·네온 금지 */
```

- 버튼·카드 radius는 `--r-lg`(22) 기본. 완전 알약형(pill)은 작은 칩·배지에만.
- 그림자는 **낮고 넓게** 한 겹. `BRAND.md` §6-2 "반투명 유리 효과 없음"과 정합.

### 2-4. 터치 · 모션 토큰 — `BRAND.md` §2-2·§6-6에서 파생

```
--tap-min:        56px;   /* 부모 최소 터치 타깃 (WCAG 2.5.5 AAA 44px 초과) */
--tap-min-child:  44px;   /* 자녀 웹 */
--record-btn:     min(72vw, 320px);  /* 큰 녹음 버튼: 화면 폭의 대부분, 상한 320 */

--motion-dur:     360ms;  /* 전환 기본. 300~450ms 범위 */
--motion-ease:    cubic-bezier(0.22, 0.61, 0.36, 1);  /* ease-out. 튕김·스프링 없음 */
--breathe-period: 4s;     /* 숨 쉬는 원 주기, 크기 변화 ±6% */
```

- **스와이프 제스처에 기능을 걸지 않는다**(손떨림, BRAND §2-2). 삭제·다음 같은
  동작은 명시적 버튼으로.
- `prefers-reduced-motion`: 숨 쉬는 원은 **정지 + 색 변화만**, 화면 전환은 즉시 교체.
- 진동: 부모 앱은 녹음 시작·끝 각 1회만. 알림 진동은 시스템 기본.

## 3. 컴포넌트 규칙

> 각 컴포넌트를 **부모용·자녀용 두 밀도**로 명세한다. 문구는 §9 화자 규칙·용어집을
> 따른다. 상태 배너는 팀 규칙 6(오류 코드)을 컴포넌트 층위로 강제한다.

### 3-1. 버튼

| | 부모용 | 자녀용 |
|---|---|---|
| 주요(Primary) | `--primary` 배경, `--on-primary` 글자, 높이 **56px+**, 글자 22/600, radius 22, **화면당 하나** | `--primary`, 높이 48px, 글자 16/600 |
| 보조(Secondary) | `--surface` 배경 + `--line-strong` 테두리 1.5px, `--ink` 글자 | 동일 축소 |
| 텍스트 버튼 | 밑줄 없는 `--primary` 텍스트, 큰 텍스트 대비(19px 굵게↑) | 표준 링크 |
| 규칙 | 아이콘 단독 버튼 금지 — **항상 글자 라벨**. "말하기"·"다 했어요"처럼 동사 | 아이콘+라벨 허용 |
| 비활성 | `--muted` 글자 + `--line` 면. **부모 화면엔 비활성 버튼을 되도록 두지 않음**(할 수 없는 걸 보여주면 불안) | 표준 disabled |

### 3-2. 큰 녹음 버튼 + 숨 쉬는 원 (부모 전용 — 이 제품의 심장)

- 지름 `--record-btn`(화면 폭의 대부분). 화면 중앙. **원 = BRAND ㉮ 심볼의 두 호가
  맞닿아 만드는 형태**(BRAND §6-4). 마이크 아이콘·파형 없음.
- 상태별 표현(색·문장·모션 함께 — 색만으로 상태 전달 금지):

| 상태 | 원 | 버튼 라벨 | 보조 문장 |
|---|---|---|---|
| 인터뷰어가 말하는 중 | 4초 주기로 천천히 부품(±6%), `--primary-soft` | (없음) | (질문 자막이 위에) |
| 말할 수 있음(대기) | 정지, `--line-strong` 윤곽 | **말하기** | "편하실 때 말씀하세요" |
| 부모가 말하는 중 | `--primary`로 옅게 차오름 | **다 했어요** | (자동 턴 전환 VAD가 기본, 버튼은 폴백) |
| 정리 중 | 아주 느린 맥동, `--accent-soft` | (비활성) | "정리하고 있어요" |
- `prefers-reduced-motion`: 부풂 대신 색만 변화(BRAND §6-6).
- **재녹음**: "다시 말할래요" 텍스트 버튼(원 아래). 방금 턴만 버리고 같은 질문 재시작.
  스와이프로 삭제 금지(DP3).

### 3-3. 질문 카드 (부모)

- 인터뷰어 도입 1문장 + 본 질문 1개. 질문은 `--fs-question`(28/600), `--ink`.
- 질문은 TTS로도 읽어 준다("다시 듣기" 텍스트 버튼 1개).
- 카드 배경 `--surface`, 위쪽에 어제 잇는 한 줄이 있으면 `--muted`로 작게
  ("어제는 진주 앞바다 얘기 하셨죠").

### 3-4. 응원 카드 (부모가 받음 / 자녀가 씀)

- 부모: 인터뷰 도입부에서 인터뷰어가 **읽어 준다** + 카드로도 표시. "지영 씨가
  한마디 남겼어요" → 자녀 문장. `--primary-soft` 배경, `--ink` 글자.
- 자녀 작성: 1일 1건, 한 줄 입력(140자). 광고성 아닌 정보성(§5). 게임화 배지 없음.

### 3-5. 출석 표시 (부모) — 달력, 게임화 금지

- **달력에 표시**만 한다(BRAND §1-4 A4). 한 날 = `--accent`(쑥빛) 점 하나 + 날짜.
- **금지**: 연속 기록 카운터·스트릭·불꽃·별·도장·"며칠째"·깨짐 경고. "몇 번째"는
  중립 표현으로만("스무 번째 얘기예요"), 압박으로 쓰지 않는다.
- 쉰 날은 빈칸(회색 X·경고 아이콘 금지). "쉬셨어요"는 문장으로만, 색 강조 없음.

### 3-6. 상태 배너 (로딩·오류·오프라인) — 팀 규칙 6을 컴포넌트로 강제

두 밀도가 **가장 크게 갈리는 컴포넌트.** 오류 코드 규칙이 여기서 강제된다.

| | 부모용 | 자녀용 |
|---|---|---|
| 색 | `--warn`/`--accent-soft`/`--surface` — **빨강(`--error`) 금지** | `--warn`·`--error` 사용 |
| 문안 | 사람 말투 한 문장. "잠깐 안 돼요, 조금 있다 다시 열어 주세요" | 문장 + **원인 코드** 말미: "정리 중 오류 (`stt.failed`) — 다시 시도" |
| 코드 노출 | **절대 없음**(BRAND §5-2, 팀 규칙 6) | **항상**(로그와 대조·QA 스크린샷 판별) |
| 로딩 | 스피너 대신 문장: "정리하고 있어요" · 3초↑ "조금 걸려요. 기다려 주세요"(BRAND §6-6) | 스켈레톤/스피너 + 문장 |

원인 코드 사전은 **PRD §4-6**(부모·공통 표면)과 **ARCHITECTURE §4**(자녀·시스템
전용 `family.*` 등)에 나뉘어 있다 — 컴포넌트는 두 곳의 키를 **참조만** 한다
(새 코드를 만들지 않는다, 팀 규칙 8 단일 진실 공급원).

### 3-7. 리스트 (자녀 — 일일 스토리·주간 요약)

- 카드 리스트. 한 항목 = 날짜(`--muted`) + 사실 한 줄(`--ink`) + 부모 발췌 한 문장
  (`--ink-2`, 큰따옴표, 원문 그대로). 최신이 위.
- 부모가 쉰 날 항목: "오늘은 어머니가 쉬셨어요" — 죄책감 문구·경고색 금지(§5).

### 3-8. 모달 / 바텀시트

- 부모: **전체 폭 바텀시트**, 큰 버튼 하나, 닫기는 명시적 버튼("닫기"). 뒤 배경 탭으로
  닫히지 않게(실수 방지, DP3). 최대 2개 선택지.
- 자녀: 표준 모달, ESC·배경 탭 닫기 허용.
- 동의·삭제·환불 같은 비가역 확인은 **부모는 음성+버튼**, 자녀는 명시적 이중 확인.

## 6. 스토어 스크린샷 레이아웃 · 캡처 설계

> **문구는 GROWTH, 레이아웃·캡처 설계는 PD**(TEAM.md §2 PD↔GROWTH). 톤 원본은
> `BRAND.md` §8-2. **채록의 하드 규칙: 순수 캡처 기반으로 설계한다 — 그라데이션+목업
> 합성은 App Store 2.3.3 promotional 판정으로 반려된다**(PD 하네스). 24장 재작업
> 사고가 이 규칙을 낳았다.

**캡처 원칙 (반려 방지):**
1. **실제 앱 화면 캡처가 프레임의 주체.** 배경 그라데이션 위에 기울인 목업을 얹지
   않는다. 배경은 `--bg` 한지색 단색 또는 캡처가 화면을 꽉 채운 형태.
2. 캡션은 화면 **위/아래 여백**에 얹되, 캡션이 스크린샷 면적의 다수를 차지해
   "광고 이미지"로 보이지 않게 한다. 캡션 28px 이상(BRAND §8-2).
3. **"AI" 문구 없음**(BRAND A2). "자동 생성"류 금지.
4. **헤드라인과 화면이 모순되지 않게**(PD 하네스 규칙, 렉시오 심사 교훈) — "말만
   하면 됩니다" 캡션 아래에는 반드시 "말하기" 버튼 하나뿐인 화면.

**부모 앱 스토어 8장 레이아웃 (문구 슬롯은 GROWTH가 채움):**

| # | 캡처 화면 | 캡션 슬롯(GROWTH) | 왜 이 순서 |
|---|---|---|---|
| 1 | 인터뷰 대기 — "말하기" 버튼 하나 + 숨 쉬는 원 | 배울 게 없다는 약속 | **첫 장이 제품의 실체**(단일 동작) |
| 2 | 오늘 질문 카드(첫 월급 얘기) | 매일 질문 하나 | 반복 장면 |
| 3 | 마무리 발화 — "지영 씨한테 한 줄 보낼게요" | 자녀에게 안부가 간다 | 두 청중 연결 |
| 4 | 선물 개봉(자녀 편지) | 딸이 보낸 선물 | 획득 서사 |
| 5 | 달력(출석, 게임화 없음) | 부담 없는 리듬 | 지속 |
| 6 | 나만 보기 토글 | 프라이버시 안심 | 이탈 방어 |
| 7 | 완주 — 한 권이 된 책 | 석 달 뒤 한 권 | 보상 |
| 8 | 다크 모드 인터뷰 화면 | 저녁에도 편하게 | 저조도 |

**자녀 웹 랜딩 캡처(스토어 아님, GROWTH 랜딩용 레이아웃):** 사진 우선(BRAND §6-5
실제 60~70대 손·식탁) → 헤드라인 → 3단계(신청→매일 답→한 권) → 가격. 부모 발췌
한 문장을 실물처럼 보여주되 조작된 후기로 오해될 문구는 넣지 않는다.

## 7. PD → APP / FE 핸드오프 노트

> 완성 전에 보여준다(PD 하네스). 아래는 **구현 착수 전 APP/BE/FE에 먼저 물을 것**과
> **넘기는 것**이다. 설계 후 "그건 안 됩니다"가 가장 비싸다.

**APP(부모 앱)에 먼저 확인할 것:**
1. **숨 쉬는 원 + 자동 턴 전환(VAD)** 의 실기기 반응 — 4초 침묵 판정이 느린 발화를
   자르지 않는가(TECH_SPIKE S3). 자르면 버튼 폴백을 기본으로 승격해야 하므로 설계가
   바뀐다.
2. **화면 유지(keep-awake) + 전체 화면**에서 통화 은유가 서는가. 백그라운드 녹음은
   V1.0에서 빼고(X13) 화면 유지로 대체 — 이때 "화면을 켜 두세요" 안내가 필요한가.
3. **마이크 권한 재요청 UX** — iOS에서 한 번 거부하면 설정으로 보내야 한다. 그
   안내 화면(§4 P2 권한 거부 상태)의 실제 딥링크 가능 여부.
4. **시스템 글자 확대 200%** 에서 인터뷰 화면이 버티는가(고정 높이 없이).

**FE(자녀 웹)에 넘기는 것:** 토큰(§2)·컴포넌트(§3)·반응형(§5). 결제 화면의 원인
코드 노출(팀 규칙 6)은 BE 오류 계약(TECH_SPIKE §5-4)과 맞춘다.

**BE에 맞출 것:** §4-6 오류 코드 사전이 TECH_SPIKE §5-4의 로그 `code`와 **같은
문자열**이어야 한다(자녀 화면 배너 = 로그 = QA 스크린샷 삼자 대조). 어긋나면 코드가
있어도 진단이 안 된다.

**BRAND에 되물을 것(색·톤 원본이라 PD가 못 정함):** 없음 — §2 토큰은 전부 BRAND
§6에서 파생됐고 새 색을 만들지 않았다. 간격·radius·그림자는 브랜드 소유가 아니므로
PD가 정했다. 다만 **이름 미확정**(§10-E)이라 화면 내 브랜드명 리터럴은 `〔서비스명〕`
placeholder로 두었다 — 이름 확정 시 일괄 치환.
