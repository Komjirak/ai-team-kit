### 한 줄 결론

**"매일 통화하듯 답하면 자서전이 된다"는 턴 기반(누르고 말하기) 녹음으로 V1에서 실현 가능하다.**
실시간 대화·전화·영상은 원가와 실패 모드 때문에 V1에서 뺀다. 채널은 **자녀=웹, 부모=앱(무료)**이
경계가 가장 깨끗하고, 알림톡은 두 쪽 모두의 보조 채널로 쓴다. 카카오톡 인앱 브라우저 안에서 녹음하는
설계는 하지 않는다.

## 2. 채널 아키텍처 3안 비교

전제: 사용자는 둘이다. **자녀(구매·설정·응원·열람)**와 **부모(매일 답하기)**. 마찰이 문제가 되는 쪽은
부모다. 자녀는 20~50대이고 웹으로 충분하다. 그래서 세 안은 "부모가 어디서 답하는가"의 차이다.

| 축 | (A) 알림톡 → 모바일 웹 (웹뷰 없음) | (B) 알림톡 → 웹, 나중에 앱 | (C) 앱 우선(스토어) + 알림톡 보조 |
|---|---|---|---|
| 부모 진입 마찰 | 설치 없음. 매일 링크 탭 → **카톡 인앱 브라우저 → 외부 브라우저로 탈출**(한 번 더 탭 또는 자동 리다이렉트) → 마이크 권한(iOS Safari는 사이트별 "허용" 기억을 사용자가 설정해야 매번 안 뜸) | A와 같다가 앱 설치 시점에 C로 전환 | **설치 1회**(자녀가 해 줌 또는 알림톡 AL 버튼 → 스토어). 이후 권한 1회. 매일은 푸시/알림톡 탭 → 앱 |
| 마이크 | 외부 브라우저에서만 신뢰 가능. 카톡 인앱은 **불가로 간주** | 동일 | 네이티브 권한. 안정 |
| 백그라운드·화면 잠금 | **불가.** 화면 꺼지면 녹음 끊김. 턴을 짧게 끊어야 함 | 동일 → 앱 전환 후 해결 | `UIBackgroundModes: audio`로 가능(심사 시 정당성 설명 필요). 화면 켜짐 유지(keep-awake)가 기본 |
| 푸시 | 없음(iOS 웹 푸시는 홈 화면 설치 PWA만). **알림톡 의존 100%** | 동일 → 앱 후 푸시 | 네이티브 푸시(무료). 알림톡은 앱 미설치·미반응 시 보조 |
| 카카오 정책 리스크 | 알림톡 정보성 심사 + 인앱 브라우저 정책 변경에 노출. 탈출 스킴(`kakaotalk://web/openExternal`)은 비공식 관행 | 동일 | 알림톡은 보조라 정책 실패의 타격이 작다 |
| 개발·운영 비용 | 가장 낮음(웹 1벌). 단, 기기·브라우저 매트릭스 QA 비용은 숨어 있음 | 웹 + 앱 두 벌(웹은 자녀용으로 남으니 낭비는 아님) | 앱 + 자녀 웹. 빌드 예산·심사 리드타임(첫 심사 1~2주) |
| OTA/배포 경로 | 웹 배포 = 즉시·되돌리기 쉬움 | 웹 즉시, 앱은 OTA/빌드 | JS는 EAS OTA, 네이티브 변경은 빌드. 플레이북 규율 적용 |
| 되돌리기 난이도 | 매우 쉬움 | 쉬움 | 앱 배포는 되돌리기 비쌈(심사). 스위치 뒤에 둔다 |
| "통화하듯" 경험 | 브라우저 크롬·주소창이 보임. 통화 느낌 약함 | 동일 | 전체 화면·큰 버튼·CallKit 느낌 구현 가능 |

### 권고안: **(B′) 자녀=웹 · 부모=앱(무료) · 알림톡=양쪽 보조.** V0는 (A)로 스파이크, V1에서 부모 앱.

이유:
1. **부모의 매일 의식(ritual)은 "한 번 탭 → 바로 말하기"여야 한다.** (A)는 매일 인앱 브라우저 탈출과
   권한 프롬프트를 거치고 화면이 꺼지면 끊긴다. 시니어에게 이 셋은 각각 이탈 사유다.
2. **알림톡 하나에 리텐션을 거는 것은 정책 리스크를 사업 리스크로 만든다.** 앱 푸시가 있으면 알림톡은
   "안 열어본 날의 두 번째 노크"로 격하되고, 심사가 막혀도 서비스가 선다.
3. **결제 경계가 저절로 깨끗해진다.** 부모 앱은 아무것도 팔지 않으므로 IAP 의무가 없고, 자녀는 웹에서
   결제한다(§6). 자녀용 앱을 만드는 순간 3.1.3(b)에 따라 IAP 병행이 필요해진다.
4. 설치 마찰은 "선물"이라는 제품 서사가 흡수한다. 자녀가 명절에 부모 폰에 앱을 깔아 주고 첫 질문을
   같이 듣는 장면이 온보딩이다. (A)의 "자녀가 부모에게 매일 링크를 설명하는" 장면보다 낫다.
5. (A)를 완전히 버리지 않는다. **앱을 못 깐 부모의 폴백**으로 웹 턴 녹음을 남긴다(알림톡 AL 버튼은
   앱 미설치 시 `url_mobile`로 떨어진다). V0 스파이크도 이 웹으로 한다.

하지 말 것: 웹뷰 셸 앱(Q3). 부모 앱을 만들 거면 녹음은 네이티브(expo-audio)로 한다.

## 3. 음성 인터뷰 UI 실현성 — 4안

전제 세션: 질문 1개 + 후속 질문 2~4개, 부모 발화 합계 8분, AI 발화 3분, 12턴.

| 축 | (i) 턴 기반 녹음(누르고 말하기 / 말 끝나면 자동 종료) | (ii) 실시간 음성 대화(Realtime API) | (iii) 실제 전화(PSTN 아웃바운드) | (iv) 영상 통화 |
|---|---|---|---|---|

### V1 판정
- **V1 = (i) 턴 기반.** "통화하듯"은 UI로 만든다: 전체 화면, 인터뷰어 얼굴(정적 일러스트 + 말할 때 파형),
  큰 버튼 하나("말하기" ↔ "다 했어요"), 침묵 4초면 자동 종료 후 "더 말할까요?" 확인, 질문은 TTS로
  읽어 준다. 부모는 버튼을 누르지 않아도 되게 **자동 턴 전환(VAD)**을 기본, 버튼은 폴백.
- **(ii) 실시간은 V2 실험.** S6 스파이크에서 고령자 3명에게 gpt-realtime-mini·Gemini Live를 들려 주고
  "끊김·기다림" 체감을 본다. 원가는 §4의 실시간 열을 BD가 가격에 반영한 뒤에만.
- **(iii) 전화는 V2 후보이나 가장 큰 시장 확장 수단**(스마트폰이 없는 80대). ClawOps류 국내 API로
  스파이크 가능(S6에 묶음). 통화 시작 시 "이 통화는 자서전을 위해 녹음됩니다" 고지 필수(§5).
- **(iv) 영상은 뺀다.** 부모 사진·자녀 응원 영상은 "받는" 쪽만 지원.

## 4. AI 파이프라인

### 4-1. 구성

```
[자녀 웹] 키워드·듣고 싶은/피할 이야기 ──▶ (a) 챕터 구조 매핑 (LLM, 1회)
                                              │  12챕터 × 질문 은행(각 8~15문)
                                              ▼
[매일 06:00 스케줄러] ──▶ (b) 오늘의 질문 선택 (규칙 + LLM 재랭킹) ──▶ TTS 캐시 ──▶ 푸시/알림톡
                                              ▼
[부모 앱/웹] 턴 녹음 ──▶ Storage(opus) ──▶ (c) STT 잡 큐 ──▶ 전사(타임스탬프·신뢰도)
                                              ▼
                       (d) 턴 사이 후속 질문 (Haiku, 짧은 컨텍스트) ──▶ TTS ──▶ 다음 턴
                                              ▼
[세션 종료] ──▶ (e) 세션 정리: 화자 정리·필러 제거·사실 카드 추출·일일 스토리(300~600자) ──▶ 자녀에게 요약
                                              ▼
[기간 종료 / 주간] ──▶ (f) 챕터 편집 → 자서전 초안(PDF/전자책) ──▶ 부모 확인 ──▶ (g) POD
```

### 4-2. 단계별 설계 요점

| 단계 | 모델·서비스 | 요점 |
|---|---|---|
| (a) 챕터 매핑 | Claude Sonnet 5 (구조화 출력) | 출력 스키마 고정: `chapters[{id,title,themes[],avoid[]}]`. "피해야 할 이야기"는 **금지 주제 리스트**로 별도 저장, 이후 모든 프롬프트의 시스템 블록에 들어간다(캐시 프리픽스) |
| (b) 일일 질문 | 규칙(챕터 순서·미답·연속성) + Haiku 4.5 재랭킹 | 질문 은행에서 고르므로 **TTS를 미리 만들어 캐시**한다. 어제 답에서 이어지는 "그때 그분은 어떻게 되셨어요?" 꼴 1개를 LLM이 만든다 |
| (c) STT | 1순위 리턴제로 또는 CLOVA Speech, 2순위 Deepgram Nova-3(ko), 3순위 gpt-4o-transcribe / Gemini 2.5 Flash | **벤더 추상화(`SttProvider`)** 필수. 타임스탬프·구간 신뢰도를 받아 저신뢰 구간을 편집 단계에서 "[잘 안 들렸어요]"로 표시. 화자 분리는 불필요(1인 발화) |
| (d) 후속 질문 | Haiku 4.5, 컨텍스트 = 오늘 전사 + 금지 주제 | 100토큰 이내, 1개만, 유도 질문 금지 규칙. 실패 시 질문 은행의 예비 질문 |
| (e) 세션 정리 | Sonnet 5 (품질 필요 시 Opus 5) | 출력 3종: `cleanTranscript`(구어체 보존, 필러만 제거), `facts[]`(인물·연도·장소·사건, 각 항목에 원문 구간 id), `dailyStory`(부모 1인칭, 원문에 없는 사실 추가 금지) |
| (f) 챕터 편집 | Opus 5 (긴 컨텍스트·문체), 2패스(초안 → 사실 대조) | 챕터 입력 = 그 챕터의 `facts[]` + `cleanTranscript` 발췌. **문장마다 출처 구간 id를 붙인 중간 표현**을 먼저 만들고, 출처 없는 문장은 자동 삭제한 뒤 문체 패스 |
| 음성 입력을 LLM에 직접 | 안 함 | Claude는 2026-09 기준 오디오 입력이 없다. 음성 이해가 필요한 곳(감정·웃음)은 STT 이벤트 태그로 대체 |

### 4-3. 가드레일

- **금지 주제 회피**: 질문 생성(b)(d)에 하드 필터(키워드) + 소프트 필터(LLM 판정). 부모가 스스로 그 얘기를
  꺼내면 기록은 하되 자서전 편집(f)에서 제외하고 부모에게만 보이는 "따로 둔 이야기"로 분류.
- **민감 정보**: 주민번호·계좌·주소 패턴은 전사 단계에서 마스킹(정규식) 후 저장. 건강·가족 갈등은 마스킹하지
  않되 자녀 공개 기본값을 "부모 확인 후"로 둔다(§5).
- **환각 금지**: (e)(f)에 "원문에 없는 인물·연도·장소·감정 원인을 만들지 않는다" 규칙 + 출처 id 강제 +
  사후 검증 프롬프트(사실 카드 대조). 평가셋에서 **무출처 문장 비율 0%**가 게이트.
- **오인식**: 고유명사(지명·인명)는 자녀가 입력한 키워드를 STT 키워드 부스팅(Deepgram keyterm, CLOVA 부스팅)에
  넣는다. 저신뢰 구간은 편집에서 추측하지 않고 표시한다.
- **침묵·중단**: 턴 시작 후 8초 무음 → "천천히 하셔도 돼요" TTS 1회 → 20초 무음 → 세션 저장 후 종료
  ("내일 이어서"). 앱 전환·전화 수신 → 현재 턴까지 저장(부분 세션 허용, 멱등 재개).
- **모델 실패**: LLM 오류 시 (d)는 예비 질문, (e)는 재시도 큐(지수 백오프 3회) 후 admin 알림, 자녀 요약은
  "정리 중" 상태 노출(원인 코드 포함, 팀 규칙 6).

```
  members/{uid}                     // role: child|parent, phone(해시), displayName
  profile                           // 자녀 입력: keywords[], wantToHear[], avoid[]  (avoid는 별도 보안 규칙)
  chapters/{chapterId}              // (a) 산출물
  sessions/{yyyymmdd}               // 문서 ID = 날짜 → 하루 1세션 멱등 키
    turns/{turnId}                  // turnId = 클라이언트 UUID. audioPath, sttStatus, transcript, confidence
    summary                         // (e) cleanTranscript, facts[], dailyStory, visibility
  book/{versionId}                  // (f) 초안 버전. status: draft|parentApproved|ordered
  ledger/{eventId}                  // 알림톡·SMS·결제·POD 발송 원장 (멱등 키 = eventId)
users/{uid}                         // tier 없음(가족 단위 플랜). tierEventAt 도장은 families에
```
맵 키에 점이 들어가는 값(`context.long` 꼴)은 밑줄로 치환한다 (BE 규칙).

### 5-2. 음성 원본 보관
- 기본: **자서전 확정 후 90일 보관 → 자동 삭제**, 전사·편집본은 유지. 부모가 "목소리도 남기기"를 켜면 영구
  보관(자녀에게 "목소리 파일" 가치가 큼 — PO 결정 대기: 기본값을 어느 쪽으로).
- 저장: Cloud Storage, 서버 측 암호화 기본, 접근은 짧은 TTL 서명 URL. 원본은 STT 벤더에 전송되므로
  **벤더별 데이터 보관·학습 미사용 조항을 계약 전에 확인**한다 [확인 필요: 벤더별].
- 국외 이전: Deepgram·OpenAI·Google은 국외 처리 → 개인정보 처리방침에 국외 이전 고지 필요. 국내 리전만
  쓰려면 CLOVA/RTZR(원가 상승, §4).

### 5-3. 공개 범위·동의·계정
- **동의는 본인만.** 부모는 성년자이므로 자녀가 대리 동의할 수 없다. 자녀는 부모 번호를 등록할 때 "초대
  문자가 발송됨"만 고지받고, **부모가 첫 진입에서 직접 동의**(수집·AI 처리·국외 이전·자녀 공유)한다.
  동의 전에는 녹음 버튼이 없다.
- 공개 범위 모델(기본값은 PD·PO가 정한다. 여기서는 선택지):
  - 일일 스토리: 자녀에게 자동 공개(안부 가치) — 답변별 "나만 보기" 토글로 부모가 뺄 수 있다.
  - 원본 음성·전사: 부모만. 자녀는 자서전·일일 스토리만.
  - 자서전 초안: 부모 확인 후 자녀 공개(구매자는 자녀지만 내용 주권은 부모).
- 고령자 계정: 전화번호 + SMS OTP 1회, 이후 **초대 매직링크로 자동 로그인**, 세션 90일. 기기 바뀌면 OTP
  재인증. 익명 인증은 쓰지 않는다(플레이북의 30일 자동 삭제 사고 회피). 자녀는 카카오/이메일 로그인.
- 삭제·반출: 부모 본인 요청 시 전체 삭제(가족 단위 문서는 익명화). 반출은 ZIP(오디오+전사+PDF).
  **사망 시 자녀 승계**는 법적·정서적으로 비가역 → 약관 설계 PO 결정 대기.
- 전화(iii)를 하게 되면: 당사자 녹음은 통신비밀보호법상 적법하나, 개인정보 처리 목적 고지를 통화 첫 문장에
  넣는다("이 통화는 자서전을 만들기 위해 녹음돼요").

### 5-4. 쓰기 경로의 멱등·순서·실패 모드 (BE DoD)

| 쓰기 경로 | 멱등 키 | 순서 역전 가드 | 실패 모드 → 클라이언트가 받는 것 |
|---|---|---|---|
| 턴 업로드 → `turns/{turnId}` | 클라이언트 UUID. 같은 키 재업로드는 no-op | 없음(턴은 append) | 업로드 실패 `turn.upload_failed (network)` → 로컬 큐 재시도, 화면엔 "저장 중" |
| STT 잡 콜백 | `turnId + audioHash`. 결과 문서에 `sttEventAt` 도장 | **`writeIfNewer`**: 콜백이 늦게 두 번 오면 낡은 결과 무시 | 벤더 오류 `stt.failed (vendor_5xx)` → 백오프 재시도 3회 → admin 알림, 자녀 요약은 "정리 중" |
| 세션 정리 (e) | `sessionId + turnCount`. 같은 턴 수로 재실행이면 덮어쓰지 않음 | 새 턴이 추가되면 재실행(뒤 실행이 이김) | LLM 오류 → 재시도 큐, 부모 화면엔 영향 없음 |
| 알림톡·SMS 발송 | `ledger/{familyId}_{date}_{templateCode}` 선점 후 발송 | 스케줄러 중복 실행 시 원장 존재로 차단 | 발송 실패 코드(수신 거부·번호 오류) → 다음 채널(앱 푸시→알림톡→SMS) 폴백, 원장에 outcome |
| 결제 웹훅(토스페이먼츠) | `paymentKey`(또는 orderId) + 이벤트 타입 | `eventAt` 도장 + `writeTierIfNewer` (플레이북) | 검증 실패 `payment.verify_failed` → 200 응답하되 원장에 기록·admin 알림. 자녀 화면 "결제 확인 중 (코드)" |
| POD 주문 | `book/{versionId}` 해시 = 주문 번호 | 같은 버전 재주문 차단 | 주문 API 실패 → 수동 주문 큐(admin) |
| 수동 부여(admin) | 원장에 기록 + 같은 `eventAt` 도장 | 웹훅이 되덮지 않음 | — |

로그: 모든 경로가 `{"type":"STT_DONE","familyId":..,"sessionId":..,"outcome":"applied|skipped_stale|failed","code":..}`
한 줄을 남긴다. 실거래·실세션 검증은 이 한 줄로 끝나야 한다.

## 6. 결제·알림·책 제작

### 6-1. 결제 경계
- **자녀 = 웹 결제(토스페이먼츠, 카드 3.4%+VAT 기본. 영세·중소 우대율 적용 시 0.6~1.7%)**. 정기결제(빌링키)
  수수료·조건 [확인 필요]. 포트원 경유 시 추가 수수료 [확인 필요].
- **부모 앱은 판매 없음** → IAP 의무 없음. 앱 안에 결제·가격·구매 링크를 두지 않는다(3.1.1). "초대 코드/
  링크로 진입하는 무료 앱"이라 심사 시 데모 계정을 반드시 첨부한다.
- 자녀용 앱을 나중에 만들면 3.1.3(b)에 따라 **같은 상품을 IAP로도** 팔아야 한다. 그때는 플레이북(RevenueCat·
  웹훅·`writeTierIfNewer`)이 그대로 적용된다. 한국 한정 바이너리로 외부 결제(수수료 26%)를 쓰는 길도 있으나
  별도 바이너리·정산 보고 부담이 커서 권하지 않는다. Google Play는 한국 한정 개발자 제공 결제 허용(수수료 4%p
  인하).
- 구독형이면 웹 구독 관리 페이지(해지·환불)를 자녀 웹에 둔다. 앱스토어 구독이 아니므로 스토어 정책의 환불
  규칙이 아니라 전자상거래법을 따른다.

### 6-2. 알림
- 알림톡 단가 13원/건(솔라피, 소량 구간). 템플릿 심사 2~3영업일, 카카오톡 채널·발신프로필 등록은 사업자
  등록 + 대행사 경유로 **1~2주 리드타임 가정** [확인 필요]. 버튼은 최대 5개, WL(웹링크)은 **인앱 브라우저로
  열린다**(Q1), AL(앱링크)은 `scheme_ios/android + url_mobile` 폴백.
- 2026-01-01 개편: 정보성(계약·거래 관계에서 반드시 전달할 정보)만. 하루담의 "오늘의 질문"은 **서비스 이용
  알림**으로 심사받는다. 부모가 회원으로 수신 동의한 상태여야 하고, 자녀 구매 → 부모 수혜 구조를 템플릿
  설명에 적는다. 응원 메시지·출석 리워드는 광고성으로 분류될 위험 → 앱 푸시로만 [확인 필요: 심사 결과].
- 채널 폴백 순서: 앱 푸시(무료) → 알림톡(13원) → SMS(20원대, 광고성 아님). 원장(§5-4)에 기록.

### 6-3. 책 제작(POD)
- **스위트북 Book Print API**: REST, 주문·인쇄·배송 풀필먼트, 단가는 파트너 로그인 후 조회(B2B 비공개), 월 대량
  주문은 협의가. 파트너 가입은 대외 접촉 → PO 승인.
- 부크크·교보 바로출판: 공개 API 없음(수동 업로드). 첫 100권은 admin에서 PDF 내려받아 수동 주문해도 운영
  가능. 권당 제작비(컬러 200p) [확인 필요, 소비자가 기준 1.5~2.5만원 추정].
- 파이프: 자서전 확정(부모 승인) → PDF/X 생성(서버, 폰트 임베드) → 표지 템플릿 → 주문 → 배송 추적 웹훅 →
  자녀 알림. PDF 생성은 결정론적으로(같은 버전 = 같은 파일 해시) 만들어 재주문 멱등을 지킨다.

## 8. V0 · V1 기술 범위 제안 (PM이 자를 재료)

### V0 (2주) — "5~10가정이 14일 동안 매일 답한다"
- 부모: **모바일 웹**(외부 브라우저 강제) 턴 녹음. 질문은 미리 만든 은행 30개 + TTS 캐시. 로그인은 매직링크.
- 자녀: 구글 폼 수준의 키워드 입력 + 매일 저녁 일일 스토리를 **수동 카톡/이메일**로 전달(컨시어지).
- 서버: Storage 업로드 → STT(2개 벤더 병렬 저장) → (e) 세션 정리 → admin 시트.
- 결제·알림톡·책 없음. 알림은 SMS(솔라피) 또는 사람이 보낸다.
- 측정: 완주율·발화 길이·마이크 실패율·CER·"내일도 하고 싶다" 응답. S1·S2·S4를 여기서 소화.
- 게이트: 완주율 60%↑, CER 후보 1개가 12%↓, 마이크 실패 5%↓. 하나라도 미달이면 V1 채널 재검토.

### V1 (6~8주) — "선물 → 매일 통화 → 90일 뒤 초안"
- 부모 앱(Expo, iOS/Android, 무료): 통화형 턴 UI, 자동 턴 전환, 푸시, 초대 딥링크, 답변별 나만 보기, 오프라인 큐.
  백그라운드 녹음은 **스위치 뒤**(1.0은 화면 유지로 대체).
- 자녀 웹: 구매(토스페이먼츠), 키워드·피할 이야기 입력, 부모 초대, 일일 스토리 열람, 응원 메시지 1일 1건, 주간 요약.
- 알림: 앱 푸시 → 알림톡(템플릿 2종) → SMS 폴백.
- 파이프라인: (a)~(f) 전부, 벤더 추상화, 평가셋 게이트, 구조화 로그.
- 자서전: 전자책(PDF) 초안 + 부모 확인 화면. 실물 책은 **admin 수동 주문**.
- admin: 가족 상태·세션·STT 실패·발송 원장·수동 부여·POD 큐.
- 뒤로 미룸: 실시간 대화, 전화, 영상, 자녀 앱, POD 자동화, 일본어, 목소리 보관 옵션, 출석 리워드 자동화.

### 배포 경로·주체
- 웹(자녀)·서버: CI에서 배포 가능한 구조로 만든다(Firebase 배포 인증은 CI 시크릿). 로컬 배포면 `git pull` →
  배포 → 성공 문자열 확인 절차를 문서화.
- 부모 앱: 첫 출시는 네이티브 빌드(심사 1~2주 리드타임을 V1 일정 뒤에 붙인다). 이후 JS는 OTA. 네이티브
  모듈(expo-audio·푸시·keep-awake)은 첫 빌드에 전부 넣고 이후 추가를 피한다.
