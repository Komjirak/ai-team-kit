## 0. 요약 (한 문단)

이 제품의 승부처는 AI 자서전 기능이 아니라 **지속 설계**다 — "데일리 습관(하루 한
질문) × 자녀 피드백 루프 × 1년 뒤 책"의 결합은 어느 경쟁자에게도 없다
(BUSINESS_CASE §5 경쟁 판정). 그러나 이 결합의 두 전제 — ① 자녀가 돈을 낸다(G1),
② 부모가 보상 없이 매일 답한다(G2) — 는 **아직 둘 다 미검증**이다. 그러므로 이
PRD가 정의하는 MVP는 "작은 완제품"이 아니라 **G1·G2를 최저 비용으로 판정하는
검증 장치**다. 랜딩 한 장으로 지불 의사를 재고(G1), 결제 없는 베타로 습관 전이를
잰다(G2). 두 숫자가 나오면 정식 V1로 키우고, 안 나오면 §4의 기준대로 멈춘다.

## 1. 문제 정의 — 양면 시장: 사는 사람과 쓰는 사람이 다르다

이 제품은 **자녀가 사고(구매자), 부모가 쓴다(사용자).** 문제도 두 개고, 둘 중
하나만 풀면 실패한다 — 자녀 문제만 풀면 "산 사람은 많고 채운 사람은 없는 질문책"이
되고(BUSINESS_CASE §5-3), 부모 문제만 풀면 돈 낼 사람이 없는 일기 앱이 된다.

### 1-1. 자녀(구매자)의 문제 — "더 늦기 전에"가 가리키는 결핍

승인된 카피 방향("더 늦기 전에 물어보세요 / 들어보세요", DECISIONS #3)은 기능이
아니라 결핍을 가리킨다. 문제 문장으로 옮기면:

> **부모의 이야기를 물을 수 있는 시간은 유한한데, 일상은 그 질문을 무한히 미루게
> 한다.** 명절에 물어보려다 매번 놓치고, "언젠가 여쭤봐야지"는 부모의 건강 이슈나
> 사별 앞에서야 "왜 안 물었을까"가 된다. 멀리 사는 자녀에게는 여기에 **"매일 못
> 챙긴다"는 죄책감**이 겹친다 (BUSINESS_CASE §4-3).

| # | 문제 | 지금 어떻게 되고 있나 | 왜 해결이 안 되나 |
|---|---|---|---|
| C1 | **미룸** — 물어야 한다는 걸 알지만 계기가 없다 | 명절·행사 때 몰아서 물으려다 분위기·시간에 밀림 | 1회성 이벤트로는 인생 이야기가 안 나옴 |
| C2 | **직접 묻기의 지속 불가** — 카톡으로 매일 묻는 건 공짜지만 자녀 의지가 재원이라 2주를 못 감 | 무료 대안(카톡 직접 질문)·저가 대안(1만 원대 질문책)이 존재하나 **완주가 안 됨** | 지불 명제 = "꾸준함의 자동화 + 책 완성" (R1) |
| C3 | **매일의 빈자리** — 왕래 월 1회 이하, 안부 전화는 3분 | 안부 앱(ONYU 등)은 생존 확인만 — 기록이 남지 않음 | 오늘의 안부가 내일이면 소멸 (BUSINESS_CASE §5-4) |

### 1-2. 부모(사용자)의 문제

| # | 문제 | 지금 어떻게 되고 있나 | 설계 요구 |
|---|---|---|---|
| P1 | **쓸 계기와 형식이 없다** — "자서전"은 크고 막연한 일 | 질문책은 빈 채로 남고, 제작 대행은 150만 원+ | 하루 한 질문으로 잘게 자른다 |
| P2 | **타이핑 장벽** | 긴 글 입력은 5070에게 신체적 부담 | **음성 입력 기본** (Remento 방식, G4 스파이크 대기) |
| P3 | **답할 이유가 매일은 없다** — 성찰은 현금 보상만큼 강한 동기가 아니다 | 앱테크 습관(월 28.5일 접속)은 있으나 **보상에 조건화된 행동**이다 (BUSINESS_CASE §3 함정 1) | 자녀의 반응(읽음·응원)이 되돌아오는 루프가 보상을 대신한다는 가설 — **G2의 검증 대상** |
| P4 | **설치·가입 장벽** | 앱 설치·회원가입에서 이탈 (R3) | 자녀 대리 설정 + 응답 경로 판단 (§3-3) |

### 1-3. 가치 가설 (이 PRD의 검증 대상)

> **자녀가 결제하고 매일 반응을 되돌려주면**, 부모는 현금 보상 없이도 하루 한
> 질문에 답하는 습관을 유지하고, 그 축적이 1년 뒤 책이 된다.

주의: "앱테크 습관이 보상 없는 답변으로 전이된다"는 **근거 없는 유추**다
(HARNESS "지금 상태" ③). G2가 검증하기 전까지 사실로 취급하지 않는다.
마이마더스토리(연결 루프만 만들고 트랙션 없이 중단)가 반면교사다 — 연결만으로는
안 되고, **습관 설계와 완성물(책)이 함께** 있어야 한다 (BUSINESS_CASE §5-2).

## 2. 세그먼트 — BUSINESS_CASE §4-3에서 파생

세그먼트 정의·근거·모수는 §4-3이 원본이다. 여기서는 **MVP 범위 판단에 필요한
것만** 가져온다. (중복 서술 금지 — 상세는 참조로.)

| | 1차 — "멀리 사는 딸" | 2차 — "행사 주관 맏이" | 3차 — 시니어 본인 |
|---|---|---|---|
| MVP에서 | **주 타깃. G1·G2 전부 이 세그먼트로** | **범위 밖** — 전용 기능(N빵 결제·행사 패키지) 안 만듦. 자연 유입은 막지 않음 | **제외** (V1에서 제외 — BUSINESS_CASE §4-3) |
| MVP 설계에 미치는 요구 | **구매~활성화 시차**(귀성 때 설치)와 **원격 설정**(링크 초대, 부모 회원가입 없이 시작)이 필수 요건 (R3) | — | — |

1차를 고르는 이유는 §4-3과 같다: 구매 채널의 주 사용자이고, "매일"이라는 제품
리듬과 "매일 못 챙김"이라는 결핍이 맞물리며, 상시 수요라 K5(시즌 의존)를 피한다.
**이 선택은 작업 가정이다** — 세그먼트 우선순위 확정은 PO (§7).

## 3. MVP 범위

### 3-0. 범위의 원칙

MVP는 팔 물건이 아니라 **측정 장치**다. 판단 기준은 하나: **"이것이 없으면 G1
또는 G2를 판정할 수 없는가?"** — 아니면 뺀다. 그래서 결제 시스템조차 MVP(G2
베타)에는 없다: G1은 사전예약(결제 전 단계)으로, G2는 무료 지인 베타로 잰다.
실결제는 두 게이트를 통과한 뒤 정식 V1의 일이다.

### 3-1. MVP의 핵심 루프 (넣을 것)

```
자녀: 신청 + 부모 초대(원격 설정) → 부모: 매일 질문 수신 → 음성/글로 답변
  → 자녀: 답변 도착 → 읽음·응원 반응 → 부모: 반응 확인 (루프 완성)
  → 축적: 모아보기(디지털)로 "책이 되어가는 중"이 보임
```

| # | 항목 | 왜 (어느 문제·게이트를 위해) |
|---|---|---|
| I1 | **자녀 주도 온보딩** — 자녀가 신청하고 링크로 부모를 초대. 부모 쪽 회원가입 최소화(전화번호 기반) | P4·R3. 구매~활성화 시차 전제: 초대 링크는 원격으로 완결돼야 함 |
| I2 | **하루 한 질문 배달** — 아침 정해진 시각, 질문 뱅크는 **전량 자체 제작**(R6). MVP는 고정 시퀀스(개인화 없음) | P1·C1. G2의 측정 단위 |
| I3 | **부모 답변 — 음성 우선 + 글** — 로컬은 녹음만, 변환·정리는 서버 배치(STT + LLM 후처리, 밤사이). 원음 보존(R7 — QR 재생용) | P2. 스파이크 판정 **조건부 Go** — 실측 파일럿 1건 잔여 (§3-3) |
| I4 | **자녀 피드백 루프** — 답변 도착 알림 → 자녀가 읽음·응원(이모지/한마디) → 부모에게 되돌림 | P3·R2. **이 제품의 차별점 그 자체** — 경쟁 판정의 "자녀 피드백 루프" |
| I5 | **모아보기(디지털)** — 쌓인 답변을 날짜·주제로 열람, 진행감 표시 | P3. "1년 뒤 책"의 선행 신호를 베타 4주 안에 보여주는 유일한 방법 |
| I6 | **미응답 회수** — 부모 무응답 시 리마인드 1회 + 자녀에게 상태 노출("이번 주 3/7") | G2 응답률을 지키는 최소 장치. 잔소리 톤 금지(카피는 PD·§9) |
| I7 | **G1 랜딩 페이지** — 사전예약 수집. 카피는 §5-1 | G1 판정 장치. 제품과 별도로 먼저 나감 |

### 3-2. 응답 경로 — 판정: **B안(부모용 네이티브 앱) 권고로 재상신** *(2026-08-25 스파이크 반영)*

부모가 질문을 받고 답하는 경로. R3(시니어 온보딩·구매~활성화 시차·원격 설정)과
직결된다. APP 스파이크(`apps/senior-diary/docs/SPIKE_MVP_TECH.md` §B, 2026-08-25
완료)의 판정이 나왔고, **PM의 이전 잠정 권고("G2 베타는 A안 카카오+웹")를
철회한다.** 이전 권고에 스스로 달아둔 무효 조건이 그대로 실현됐기 때문이다:

1. **카카오 챗봇 단독 경로는 음성 답변을 받을 수 없다** (스파이크 경로② 판정 —
   챗봇 스킬은 텍스트 발화 기준으로만 동작, 사용자 음성메시지를 스킬 서버로 받는
   공식 경로 확인 실패). 음성 입력은 R2 완화책의 핵심이므로(§1-2 P2) 텍스트
   온리는 제품 명제와 충돌한다.
2. A안의 남은 변형(알림톡→웹 녹음, 스파이크 경로③)도 **"가장 싸고 빠르다"는
   전제가 깨졌다**: 카톡 인앱 브라우저 마이크 동작 `미확인`(실기기 검증 필요) +
   "매일 질문" 알림톡 템플릿 심사 통과 `미확인`(유사 선례 없음, 2026 심사 강화
   추세) + 단가 월 24만~42만 원/1,000명(푸시는 0원) + 웹 녹음 표면의 개발·QA
   +2~3주.

**재상신안 (→ §7 D3):**

## 4. 성공 기준 — 숫자로 판정한다

BUSINESS_CASE의 G1~G4·K1~K5와 어긋나는 숫자를 만들지 않는다. MVP 단계에서
판정하는 것은 **G1·G2·G4**이고, K3~K5는 정식 출시 후의 감시 항목이라 이 PRD의
판정표에 넣지 않는다 (원본: BUSINESS_CASE §1·§2).

| 게이트 | 지표 | 다음 단계 진행 | 중단/재설계 | 원본 |
|---|---|---|---|---|
| **G1** 지불 수요 | 랜딩 방문→사전예약 전환 (표본 ≥1,000 방문) | **≥3%** → G2·정식 V1 준비 진행 | **<3% → 착수하지 않음** (K1) | G1·K1 |
| **G2** 부모 지속 | 베타 4주차 **주간 응답률** (주 7문 중 답한 비율의 가족 평균이 아니라, **주 1회 이상 답한 가족 비율** — 측정 정의는 아래) | **≥50%** → 정식 V1 착수 상신 | 30~50%: 원인 분석 + 재설계 1회 후 PO 판단 · **<30%가 2개 코호트 연속 → 재설계 1회 → 8주차 <20%면 중단** (K2) | G2·K2 |
| **G4** 입력 실현성 | 고령자·사투리 **실측 CER** — AI Hub 노인남여 샘플 30~50문장, 후보 3개(RTZR·gpt-4o-transcribe·클로바) 비교 (스파이크 §A는 조건부 Go — 실측만 남음) | **후처리 후 CER ~10% 이하** `추정 기준, 스파이크 §A-6` → 음성 우선(I3) 확정 + 스택 선정(품질 동급이면 1/4 가격인 OpenAI 스택) | 불합격 → "글 우선 + 음성 보조"로 재설계. 파인튜닝·커스텀 계약은 MVP 이후 과제 (중단 아님) | G4 · 스파이크 §A |

**측정 정의 (G2 — 미리 못 박는다, 사후 해석 금지):**
- 주간 응답률 = 해당 주에 **1건 이상 답변한 가족 수 ÷ 활성화된 가족 수**. K2의
  "주간 응답률"과 같은 정의를 쓴다.
- 코호트 = 같은 주에 활성화된 가족 묶음. 10~20가족이면 코호트 1~2개다 — K2의
  "2개 코호트 연속" 판정에는 표본이 빠듯하므로, 베타에서 <30%가 나오면 코호트를
  기다리지 않고 재설계에 들어간다 (K2 취지의 보수적 적용).

**보조 지표 (판정 기준 아님, 제안치 — 정식 V1의 기준선을 만들기 위해 측정만 한다):**

| 지표 | 제안 목표 | 왜 재나 |
|---|---|---|
| 활성화율: 초대 발송→부모 첫 답변 (14일 내) | ≥70% `제안` | R3(온보딩·시차)의 실측. <50%면 응답 경로(§3-2) 재판단 |
| 자녀 반응률: 부모 답변에 48시간 내 읽음/응원 | ≥60% `제안` | 피드백 루프는 자녀가 끊어도 죽는다 — R2의 반대편 |
| 일 응답 소요 시간 (부모, 수신→완료) | 10분 이내 중앙값 `제안` | 부담이 크면 습관이 안 된다 |

| 항목 | 내용 |
