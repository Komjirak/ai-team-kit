## 0. 요약 (한 문단)

이 제품의 승부처는 AI 자서전 기능이 아니라 **지속 설계**다 — "데일리 습관(하루 한
질문) × 자녀 피드백 루프 × 1년 뒤 책"의 결합은 어느 경쟁자에게도 없다
(BUSINESS_CASE §5 경쟁 판정). 그러나 이 결합의 두 전제 — ① 자녀가 돈을 낸다(G1),
② 부모가 보상 없이 매일 답한다(G2) — 는 **아직 둘 다 미검증**이다. 그러므로 이
PRD가 정의하는 MVP는 "작은 완제품"이 아니라 **G1·G2를 최저 비용으로 판정하는
검증 장치**다. 랜딩 한 장으로 지불 의사를 재고(G1), 결제 없는 베타로 습관 전이를
잰다(G2). 두 숫자가 나오면 정식 V1로 키우고, 안 나오면 §4의 기준대로 멈춘다.

## 1. 문제 정의 — 양면 시장: 사는 사람과 쓰는 사람이 다르다

이 제품은 **자녀가 사고(구매자), 부모가 쓴다(사용자).** 문제도 두 개고, 둘 중
하나만 풀면 실패한다 — 자녀 문제만 풀면 "산 사람은 많고 채운 사람은 없는 질문책"이
되고(BUSINESS_CASE §5-3), 부모 문제만 풀면 돈 낼 사람이 없는 일기 앱이 된다.

### 1-1. 자녀(구매자)의 문제 — "더 늦기 전에"가 가리키는 결핍

승인된 카피 방향("더 늦기 전에 물어보세요 / 들어보세요", DECISIONS #3)은 기능이
아니라 결핍을 가리킨다. 문제 문장으로 옮기면:

> **부모의 이야기를 물을 수 있는 시간은 유한한데, 일상은 그 질문을 무한히 미루게
> 한다.** 명절에 물어보려다 매번 놓치고, "언젠가 여쭤봐야지"는 부모의 건강 이슈나
> 사별 앞에서야 "왜 안 물었을까"가 된다. 멀리 사는 자녀에게는 여기에 **"매일 못
> 챙긴다"는 죄책감**이 겹친다 (BUSINESS_CASE §4-3).

| # | 문제 | 지금 어떻게 되고 있나 | 왜 해결이 안 되나 |
|---|---|---|---|
| C1 | **미룸** — 물어야 한다는 걸 알지만 계기가 없다 | 명절·행사 때 몰아서 물으려다 분위기·시간에 밀림 | 1회성 이벤트로는 인생 이야기가 안 나옴 |
| C2 | **직접 묻기의 지속 불가** — 카톡으로 매일 묻는 건 공짜지만 자녀 의지가 재원이라 2주를 못 감 | 무료 대안(카톡 직접 질문)·저가 대안(1만 원대 질문책)이 존재하나 **완주가 안 됨** | 지불 명제 = "꾸준함의 자동화 + 책 완성" (R1) |
| C3 | **매일의 빈자리** — 왕래 월 1회 이하, 안부 전화는 3분 | 안부 앱(ONYU 등)은 생존 확인만 — 기록이 남지 않음 | 오늘의 안부가 내일이면 소멸 (BUSINESS_CASE §5-4) |

### 1-2. 부모(사용자)의 문제

| # | 문제 | 지금 어떻게 되고 있나 | 설계 요구 |
|---|---|---|---|
| P1 | **쓸 계기와 형식이 없다** — "자서전"은 크고 막연한 일 | 질문책은 빈 채로 남고, 제작 대행은 150만 원+ | 하루 한 질문으로 잘게 자른다 |
| P2 | **타이핑 장벽** | 긴 글 입력은 5070에게 신체적 부담 | **음성 입력 기본** (Remento 방식, G4 스파이크 대기) |
| P3 | **답할 이유가 매일은 없다** — 성찰은 현금 보상만큼 강한 동기가 아니다 | 앱테크 습관(월 28.5일 접속)은 있으나 **보상에 조건화된 행동**이다 (BUSINESS_CASE §3 함정 1) | 자녀의 반응(읽음·응원)이 되돌아오는 루프가 보상을 대신한다는 가설 — **G2의 검증 대상** |
| P4 | **설치·가입 장벽** | 앱 설치·회원가입에서 이탈 (R3) | 자녀 대리 설정 + 응답 경로 판단 (§3-3) |

### 1-3. 가치 가설 (이 PRD의 검증 대상)

> **자녀가 결제하고 매일 반응을 되돌려주면**, 부모는 현금 보상 없이도 하루 한
> 질문에 답하는 습관을 유지하고, 그 축적이 1년 뒤 책이 된다.

주의: "앱테크 습관이 보상 없는 답변으로 전이된다"는 **근거 없는 유추**다
(HARNESS "지금 상태" ③). G2가 검증하기 전까지 사실로 취급하지 않는다.
마이마더스토리(연결 루프만 만들고 트랙션 없이 중단)가 반면교사다 — 연결만으로는
안 되고, **습관 설계와 완성물(책)이 함께** 있어야 한다 (BUSINESS_CASE §5-2).

## 3. MVP 범위

### 3-0. 범위의 원칙

MVP는 팔 물건이 아니라 **측정 장치**다. 판단 기준은 하나: **"이것이 없으면 G1
또는 G2를 판정할 수 없는가?"** — 아니면 뺀다. 그래서 결제 시스템조차 MVP(G2
베타)에는 없다: G1은 사전예약(결제 전 단계)으로, G2는 무료 지인 베타로 잰다.
실결제는 두 게이트를 통과한 뒤 정식 V1의 일이다.

### 3-1. MVP의 핵심 루프 (넣을 것)

```
자녀: 신청 + 부모 초대(원격 설정) → 부모: 매일 질문 수신 → 음성/글로 답변
  → 자녀: 답변 도착 → 읽음·응원 반응 → 부모: 반응 확인 (루프 완성)
  → 축적: 모아보기(디지털)로 "책이 되어가는 중"이 보임
```

| # | 항목 | 왜 (어느 문제·게이트를 위해) |
|---|---|---|
| I1 | **자녀 주도 온보딩** — 자녀가 신청하고 링크로 부모를 초대. 부모 쪽 회원가입 최소화(전화번호 기반). 신청 폼에 **부모 프로필 5~7문항**(호칭·고향·결혼/사별/이혼 상태·형제/자녀 구성·주된 일 — 결정 #4) 포함: 입력자는 자녀 — 대리 설정(R3)과 같은 자리라 부모 부담 0 | P4·R3. 구매~활성화 시차 전제: 초대 링크는 원격으로 완결돼야 함. 프로필은 I2 분기의 입력값 |
| I2 | **하루 한 질문 배달** — 아침 정해진 시각, 질문 뱅크는 **전량 자체 제작**(R6). 시퀀스는 **룰 기반 분기**(결정 #4): 프로필 조건(예: 고향=서울 → 상경 질문을 동네 질문으로 치환, 이혼·사별 → 배우자 챕터 대체) + 스킵 신호(I8) 반영. AI 생성·개인화 아님(§3-4 O7) | P1·C1. G2의 측정 단위. 어긋난 질문은 이탈 트리거(R2)라 분기는 지속 설계의 일부다 |
| I3 | **부모 답변 — 음성 우선 + 글** — 로컬은 녹음만, 변환·정리는 서버 배치(STT + LLM 후처리, 밤사이). 원음 보존(R7 — QR 재생용) | P2. 스파이크 판정 **조건부 Go** — 실측 파일럿 1건 잔여 (§3-3) |
| I4 | **자녀 피드백 루프** — 답변 도착 알림 → 자녀가 읽음·응원(이모지/한마디) → 부모에게 되돌림 | P3·R2. **이 제품의 차별점 그 자체** — 경쟁 판정의 "자녀 피드백 루프" |
| I5 | **모아보기(디지털)** — 쌓인 답변을 날짜·주제로 열람, 진행감 표시 | P3. "1년 뒤 책"의 선행 신호를 베타 4주 안에 보여주는 유일한 방법 |
| I6 | **미응답 회수** — 부모 무응답 시 리마인드 1회 + 자녀에게 상태 노출("이번 주 3/7") | G2 응답률을 지키는 최소 장치. 잔소리 톤 금지(카피는 PD·§9) |
| I7 | **G1 랜딩 페이지** — 사전예약 수집. 카피는 §5-1 | G1 판정 장치. 제품과 별도로 먼저 나감 |
| I8 | **질문 스킵 — "이 이야기는 넘어갈게요"** (결정 #4) — 부모 화면 전 질문에 스킵 + **반복 스킵 주제 자동 제외** + 자녀의 민감 주제 스위치(신청 폼·설정) | R2. **스킵은 실패가 아니라 데이터다** — G2 베타에서 주제별 스킵률이 질문 뱅크 품질의 측정기가 된다. 스킵 카피는 죄책감 없는 톤(PD, §9) |
| I9 | **책 미리보기(샘플)** — 자녀 화면에 디지털북 샘플(표지·목차·본문·QR 원음 자리) (결정 #4) | I5 보강 — "1년 뒤 책"의 선행 신호. "샘플로라도 책 화면이 보이면 설득력을 가진다"(PO). 목차는 §3-5의 챕터 구조에서 파생. 화면 설계는 PD(§9) |

### 3-2. 응답 경로 — 판정: **B안(부모용 네이티브 앱) 권고로 재상신** *(2026-08-25 스파이크 반영)*

부모가 질문을 받고 답하는 경로. R3(시니어 온보딩·구매~활성화 시차·원격 설정)과
직결된다. APP 스파이크(`apps/senior-diary/docs/SPIKE_MVP_TECH.md` §B, 2026-08-25

철회한다.** 이전 권고에 스스로 달아둔 무효 조건이 그대로 실현됐기 때문이다:

1. **카카오 챗봇 단독 경로는 음성 답변을 받을 수 없다** (스파이크 경로② 판정 —
   챗봇 스킬은 텍스트 발화 기준으로만 동작, 사용자 음성메시지를 스킬 서버로 받는
   공식 경로 확인 실패). 음성 입력은 R2 완화책의 핵심이므로(§1-2 P2) 텍스트
   온리는 제품 명제와 충돌한다.
2. A안의 남은 변형(알림톡→웹 녹음, 스파이크 경로③)도 **"가장 싸고 빠르다"는
   전제가 깨졌다**: 카톡 인앱 브라우저 마이크 동작 `미확인`(실기기 검증 필요) +
   "매일 질문" 알림톡 템플릿 심사 통과 `미확인`(유사 선례 없음, 2026 심사 강화
   추세) + 단가 월 24만~42만 원/1,000명(푸시는 0원) + 웹 녹음 표면의 개발·QA
   +2~3주.

**appetite 정합 (PM 판단):** 스파이크의 개발 추정 **6~8주**(1 APP + 1 BE 병렬,
부모+자녀 플로우+서버)는 appetite(V1 크기 = 몇 주)의 **상한 안이다 — appetite를
조정하지 않고 PO 상신도 불요.** 대신 두 가지로 못 박는다:

  없음**(내부 배포 — TestFlight/내부 테스트 트랙. 지인 10~20가족이므로 심사 대응·
  스토어 문구·공개 운영이 전부 빠진다) + admin 없음·결제 없음(§3-4 O1, 스파이크
  §C "만들지 않는 것"과 일치).
- **8주가 서킷 브레이커다.** 넘길 조짐이면 연장하지 않고 §3-4 방식으로 더 자른다
  — 1순위 축소 후보: 자녀 반응을 하트 단일로(댓글 제외), 모아보기를 단순 리스트로.

*(2026-08-26 갱신 — 결정 #4 반영)* 프로필 폼·룰 분기·스킵·책 샘플 화면의 추가
추정 **+3~5일**을 반영해도 **6주 목표는 유지한다** — 룰 분기는 AI 없는 조건 치환이고

## 4. 성공 기준 — 숫자로 판정한다

BUSINESS_CASE의 G1~G4·K1~K5와 어긋나는 숫자를 만들지 않는다. MVP 단계에서
판정하는 것은 **G1·G2·G4**이고, K3~K5는 정식 출시 후의 감시 항목이라 이 PRD의
판정표에 넣지 않는다 (원본: BUSINESS_CASE §1·§2).

| 게이트 | 지표 | 다음 단계 진행 | 중단/재설계 | 원본 |
|---|---|---|---|---|
| **G1** 지불 수요 | 랜딩 방문→사전예약 전환 (표본 ≥1,000 방문) | **≥3%** → G2·정식 V1 준비 진행 | **<3% → 착수하지 않음** (K1) | G1·K1 |
| **G2** 부모 지속 | 베타 4주차 **주간 응답률** (주 7문 중 답한 비율의 가족 평균이 아니라, **주 1회 이상 답한 가족 비율** — 측정 정의는 아래) | **≥50%** → 정식 V1 착수 상신 | 30~50%: 원인 분석 + 재설계 1회 후 PO 판단 · **<30%가 2개 코호트 연속 → 재설계 1회 → 8주차 <20%면 중단** (K2) | G2·K2 |
| **G4** 입력 실현성 | 고령자·사투리 **실측 CER** — AI Hub 노인남여 샘플 30~50문장, 후보 3개(RTZR·gpt-4o-transcribe·클로바) 비교 (스파이크 §A는 조건부 Go — 실측만 남음) | **후처리 후 CER ~10% 이하** `추정 기준, 스파이크 §A-6` → 음성 우선(I3) 확정 + 스택 선정(품질 동급이면 1/4 가격인 OpenAI 스택) | 불합격 → "글 우선 + 음성 보조"로 재설계. 파인튜닝·커스텀 계약은 MVP 이후 과제 (중단 아님) | G4 · 스파이크 §A |

**측정 정의 (G2 — 미리 못 박는다, 사후 해석 금지):**
- 주간 응답률 = 해당 주에 **1건 이상 답변한 가족 수 ÷ 활성화된 가족 수**. K2의
  "주간 응답률"과 같은 정의를 쓴다.
- **스킵(I8)은 응답이 아니다** — 주간 응답률 집계에서 스킵만 있는 주는 미응답으로
  센다. 스킵은 별도 지표(주제별 스킵률 — 질문 뱅크 품질 측정기)로만 집계한다.
- 코호트 = 같은 주에 활성화된 가족 묶음. 10~20가족이면 코호트 1~2개다 — K2의
  "2개 코호트 연속" 판정에는 표본이 빠듯하므로, 베타에서 <30%가 나오면 코호트를
  기다리지 않고 재설계에 들어간다 (K2 취지의 보수적 적용).

**보조 지표 (판정 기준 아님, 제안치 — 정식 V1의 기준선을 만들기 위해 측정만 한다):**

| 지표 | 제안 목표 | 왜 재나 |
|---|---|---|
| 활성화율: 초대 발송→부모 첫 답변 (14일 내) | ≥70% `제안` | R3(온보딩·시차)의 실측. <50%면 응답 경로(§3-2) 재판단 |
| 자녀 반응률: 부모 답변에 48시간 내 읽음/응원 | ≥60% `제안` | 피드백 루프는 자녀가 끊어도 죽는다 — R2의 반대편 |
| 일 응답 소요 시간 (부모, 수신→완료) | 10분 이내 중앙값 `제안` | 부담이 크면 습관이 안 된다 |

| L1 | 헤드 | 아이브로("사전예약") + 헤드라인 **"더 늦기 전에 물어보세요"** + 서브 1문장 | 헤드라인이 곧 히어로 — 이미지 없이 활자로. 상대안: "매일 한 질문, 1년 뒤 한 권" |
| L2 | 질문 카드 | 실제 질문 뱅크의 예시 질문 1장 (명조체, 큰 활자) | "이런 걸 묻는다"를 설명 대신 실물로 |
| L3 | 작동 방식 | 3단계: 매일 아침 질문 → 부모님은 말로 답 → 1년 뒤 한 권 | 숫자 붙은 순서 — 실제 시퀀스라 번호가 정보다 |
| L4 | 정서 블록 | 보도자료 문단(§BUSINESS_CASE §0) 파생 2~3문장 — "선물한 사람이 사실 선물을 받는다" | 상실 회피 소구의 착지점 |
| L5 | 사전예약 폼 | 연락처 1칸 + 버튼. **가격·출시일 없음** (🔒 §5-1) | 마찰 최소 — 필드 1개 |
| L6 | 신뢰 꼬리 | "가격은 정식 오픈 때 알려드려요 · 연락처는 안내 외에 쓰지 않아요" | 가격 부재를 숨기지 않고 말한다 |

**모순 금지 점검**: 랜딩에 실물 책 목업·완성 화면을 과장해 싣지 않는다 — 아직 없는
것을 있는 것처럼 보이면 안 된다(PD 규칙 "헤드라인-화면 모순"의 사전 적용). L3의
"1년 뒤 한 권"은 그림이 아니라 문장으로만.

**랜딩 상태 명세**: 로딩 — 정적 1장이라 해당 없음(폰트 로딩 중 시스템 폰트 폴백) ·
빈 — 해당 없음 · 오류 — 폼 제출 실패 시 인라인 배너 "잠시 후 다시 시도해 주세요
`reserve.submit_failed`" + 입력값 보존 · 중복 제출 — "이미 신청된 연락처예요" ·
성공 — 인라인 완료 상태로 교체("오픈 소식을 가장 먼저 보내드릴게요") · 권한 거부 —
해당 없음 · 오프라인 — 제출 버튼이 실패 배너와 동일 처리(`reserve.submit_failed
(offline)`).

### 9-3. 화면 흐름 (B안 네이티브 앱, 단일 앱 · 역할 분기)

```
[자녀]  C1 시작·신청(C1a 기본 → C1b 프로필·민감 주제) → C2 초대 보내기·대기
          ─(부모 활성화)→ C3 홈 ⇄ C4 이야기 읽기·응원 ⇄ C5 모아보기 → C6 책 미리보기
[부모]  P0 초대 진입(1회) → P1 오늘 ⇄ P2 녹음(오버레이) / P1 ⇄ P3 지난 이야기
          P1 스킵 → 대체 질문(하루 1회) → 재스킵 시 "내일 다시"
```

- **부모 상시 화면은 3개다**: P1(오늘) · P2(녹음 오버레이) · P3(지난 이야기).
  P0은 1회성 진입이고, 응원 확인·정리본 도착·**스킵(I8)**은 **P1의 상태**이지 새
  화면이 아니다.
- 부모 화면에는 탭 바·햄버거·스와이프 제스처가 없다 — 보이는 버튼이 전부다.
- 자녀 화면은 6개(C1~C6), 일반 모바일 관례를 따른다. C1은 한 화면이 아니라
  **2단계**다(아래 C1 명세). 민감 주제 스위치의 사후 변경은 C5의 부속 시트
  "질문 설정"으로 — 새 화면을 늘리지 않는다.

### 9-4. 화면별 명세 — 와이어프레임 + 상태

상태 표기 규칙: **로딩 · 빈 · 오류 · 권한 거부 · 오프라인** 5종을 모든 화면에
명세한다. 해당 없으면 "해당 없음"이라 적는다(빈칸 금지). 오류 문구에는 원인 코드를
붙인다(`stt.failed (timeout)` 꼴 — 팀 규칙 6).

#### P0 — 초대 진입 (부모, 1회)

```
┌──────────────────────┐
│  따님 지혜님이            │  ← 초대한 자녀의 호칭·이름 (자녀가 입력한 값)
│  어머니의 이야기를         │
│  기다리고 있어요           │
│                      │
│  [ 시작하기 ]  ← 화면의 유일한 버튼
└──────────────────────┘
```

| 상태 | 명세 |
|---|---|
| 로딩 | 링크 검증 중 — 문장만("잠깐만요, 초대장을 확인하고 있어요"). 스피너 금지(불안 유발), 1초 내 목표 |
| 빈 | 해당 없음 |
| 오류 | 링크 만료/무효: "초대장이 오래되어 새로 필요해요. 따님께 다시 받아 주세요 `invite.link_expired`" — 부모에게 해결을 시키지 않고 자녀에게 되돌린다(자녀 앱에 재발급 버튼) |
| 권한 거부 | 해당 없음 (이 화면은 권한 요청 없음 — 마이크·알림 권한은 처음 필요한 순간에 각각 요청) |
| 오프라인 | "인터넷이 연결되면 다시 열어 주세요 `invite.verify_failed (offline)`" |

#### P1 — 오늘 (부모 홈) ⭐ 반복 장면 M2

```
┌──────────────────────┐
│ 8월 26일 화요일 · 스물세 번째 질문 │
│ (응원 도착 시) 💛 지혜님이 응원을 보냈어요 → 탭하면 P1 안에서 펼침
│                      │
│  “처음 서울에            │  ← 질문: 명조체, 28pt+, 화면의 주인
│   올라오던 날,           │
│   기억나세요?”           │
│                      │
│   ⏺ [ 눌러서 이야기해 주세요 ] │ ← 유일한 주 행동. 지름 96pt+
│                      │
│  이 이야기는 넘어갈게요       │  ← 스킵 (I8, 보조 행동 — 주 버튼보다 작게, 타깃은 64pt 유지)
│  지난 이야기 보기 →        │  ← 보조 링크 (P3)
└──────────────────────┘
```

- 답변 완료 후 상태: 질문 카드가 "오늘 이야기를 남기셨어요 ✓ / 밤사이 글로 정리해
  드릴게요"로 바뀐다. **녹음 직후 화면에 자동 받아쓰기 텍스트를 보여주지 않는다**
  (스파이크 §A-4 — 오인식 노출은 시니어를 위축시킨다).
- 정리본 도착 후(다음 날): 어제 질문·정리된 글·딸의 응원이 카드로 표시 → 오늘
  질문으로 이어짐.
- **스킵(I8) 동작 — 확정 규칙**:
  1. 스킵 즉시 **대체 질문으로 치환**한다(같은 챕터 우선, 없으면 다음 슬롯).
     확인 대화상자 없음. 카드 상단 한 줄: "그럴 수 있어요. 다른 이야기를
     여쭤볼게요." — 토스트 금지(시니어는 토스트를 놓친다).
     *내일로 미루지 않고 즉시 치환하는 이유*: 스킵이 "오늘 끝"이 되면 스킵 버튼이
     응답률(G2)을 깎는 장치가 된다 — 스킵의 목적은 회피가 아니라 계속하게 하기다.
  2. **치환은 하루 1회.** 대체 질문도 스킵하면: "오늘은 쉬어가도 돼요. 내일 새
     질문으로 찾아올게요." — 카드가 휴식 상태로 바뀌고 주 버튼은 사라진다(강요
     없음). 스킵만 한 날은 §4 측정 정의상 미응답으로 집계(측정 정의 불변).
  3. **반복 스킵 주제 자동 제외(I8)는 내부 규칙이다** — 임계값·제외 사실을 부모
     문구에 노출하지 않는다("이 주제는 그만 여쭐게요" 같은 통보 금지 — 규칙 노출은
     스킵을 감시로 바꾼다). 결과는 질문 시퀀스에만 조용히 반영.
  4. **스킵 이벤트는 자녀에게 노출하지 않는다** — "어머니가 이 질문을 넘겼어요"는
     죄책감의 전가다. 자녀에게는 응답 여부(이번 주 3/7)만 보인다. 주제별 스킵률은
     운영 데이터로만 수집(G2의 질문 뱅크 품질 측정기 — I8 취지).

| 상태 | 명세 |
|---|---|
| 로딩 | 질문 불러오는 동안 어제까지의 화면 유지 + "오늘 질문을 가져오고 있어요" 한 줄. 전체 화면 스피너 금지 |
| 빈 | 첫날(답변 0건): 지난 이야기 링크 숨김 — 갈 곳 없는 문을 보여주지 않는다 |
| 오류 | "질문을 가져오지 못했어요. 아래를 눌러 다시 시도해 주세요 `question.fetch_failed`" + [다시 시도] (재시도가 주 행동 자리를 차지) |
| 권한 거부 | 알림 거부 시에도 앱 사용 무제한 — P1 하단에 "알림을 켜면 아침마다 질문을 알려드려요" 1줄 + [켜기]. 강요 배너 금지 |
| 오프라인 | 마지막으로 받은 질문 표시 + "지금은 인터넷이 없어도 녹음은 하실 수 있어요" — **녹음은 로컬이므로 오프라인에도 가능** (업로드는 연결 후 자동, §C 스택 전제) |

#### P2 — 녹음 (부모, 전체 화면 오버레이) ⭐ 반복 장면 M3

```
┌──────────────────────┐
│  “처음 서울에 올라오던 날…” │ ← 질문이 계속 보인다 (말하다 잊지 않게)
│                      │
│      ● 0:42          │ ← 경과 시간. 남은 시간·제한 표시 없음
│    (숨쉬는 원 애니메이션)   │
│  천천히, 편하게 말씀하세요    │
│  쉬어가도 녹음은 이어져요     │ ← 멈칫 허용을 문장으로 보증 (스파이크: 1~3분·중간 멈칫 전제)
│                      │
│  [ 다 했어요 ]           │ ← 유일한 버튼
└──────────────────────┘
   ↓ 다 했어요
│  잘 들었어요.            │
│  밤사이 글로 정리해 드릴게요. │ ← STT 배치 전제를 약속의 언어로
│  ▶ 방금 하신 말씀 들어보기   │ ← 원음 즉시 재생 (정리본은 없어도 원음은 있다)
│  [ 오늘은 여기까지 ]       │
```

| 상태 | 명세 |
|---|---|
| 로딩 | 해당 없음 (녹음은 로컬 — 시작 지연 없음) |
| 빈 | 3초 미만 녹음 후 "다 했어요": "짧게 담겼어요. 이대로 보낼까요?" [보내기 / 다시 이야기하기] — 실수 탭 방어 |
| 오류 | 업로드 실패: "이야기는 폰에 잘 저장됐어요. 인터넷이 연결되면 자동으로 보내드려요 `answer.upload_failed (offline)`" — **녹음 유실 없음을 먼저 말한다.** 서버 오류: `answer.upload_failed (server)` + 자동 재시도 |
| 권한 거부 | 마이크 거부: "말씀을 담으려면 마이크 허락이 필요해요" + [허락하러 가기](설정 딥링크) `record.mic_denied`. 대안으로 [글로 쓸게요](최소 텍스트 입력) 제공 — I3 "음성 우선 + 글" |
| 오프라인 | 녹음·로컬 저장 정상 동작. 종료 화면에 "인터넷이 연결되면 자동으로 보내드려요" 추가 |

#### P3 — 지난 이야기 (부모)

날짜 내림차순 리스트. 항목 = 날짜 · 질문 · 상태(정리된 글 / 🌙 밤사이 정리 중 /
원음만). 항목 탭 → 전문 + 원음 재생 + (있으면) 딸의 응원.

| 상태 | 명세 |
|---|---|
| 로딩 | 이전 목록 유지 + 상단 1줄 "새 이야기를 확인하고 있어요" |
| 빈 | "첫 이야기를 남기면 여기에 차곡차곡 쌓여요" + [오늘 질문으로 가기] |
| 오류 | "이야기를 불러오지 못했어요 `archive.fetch_failed`" + [다시 시도] |
| 권한 거부 | 해당 없음 |
| 오프라인 | 캐시된 목록 표시 + "인터넷이 연결되면 최신 이야기를 보여드려요" |

#### C1 — 시작·신청 (자녀) — 2단계 (결정 #4 프로필 반영)

**단계 설계 판단**: 한 화면 한 질문(7화면)은 쓰지 않는다 — 입력자가 부모가 아니라
자녀(모바일 익숙, R3의 대리 설정과 같은 자리)라 과잉 분해는 오히려 이탈 요인이다.
대신 **2단계 그룹핑**: C1a(관계 — 필수 3항목) → C1b(프로필 — 선택 5문항 + 민감
주제). **MVP는 무결제(§3-0)** — 결제 UI 없음, "베타 참여" 문맥.

- **C1a 기본(필수)**: 부모 호칭(어머니/아버지) · 부모 성함 · 내 이름.
- **C1b 프로필(선택, 결정 #4의 5~7문항)**: 고향 · 결혼/사별/이혼 상태 ·
  형제 구성 · 자녀 구성 · 주로 하신 일. 전부 **선택 입력** — 미입력 항목은 기본
  시퀀스로 배달(룰 분기 없음, I2). 가치 문구로 완료를 유도한다: "알려주실수록
  질문이 어머니의 인생에 더 잘 맞아져요."
  - **분기 가시화(신뢰 장치)**: 고향 선택 시 치환 예시 1건을 그 자리에서 보여준다
    — "서울을 고르셨어요 → '처음 서울에 올라오던 날' 질문은 '어릴 적 살던 동네'
    질문으로 바뀌어요." 분기가 보여야 프로필을 채울 이유가 생긴다.
  - **민감 주제 스위치 — "여쭙지 않을 이야기"**: 배우자 이야기 · 투병·건강 ·
    돈·재산 (질문 뱅크의 주제 태그에서 파생 — 확정은 질문 뱅크 제작 시). 기본은
    전부 "여쭘". 끄면 해당 주제 제외 + 챕터 대체(§3-5). 끄는 행위를 나무라지
    않는다 — 설명 문구는 "가족마다 꺼내기 어려운 이야기가 있어요. 여기서 빼두면
    여쭙지 않아요."
  - 결혼 상태에서 "사별/이혼" 선택 시 배우자 스위치를 자동으로 묻지 **않는다** —
    챕터 대체는 룰(I2)이 조용히 처리하고, 스위치는 자녀의 명시 선택으로만 바뀐다.

| 상태 | 명세 (C1a·C1b 공통) |
|---|---|
| 로딩 | 제출 중 버튼 비활성 + "만드는 중…" |
| 빈 | C1b 전체 미입력도 유효 — "나중에 채워도 돼요" 문구와 함께 다음으로 진행 가능(빈 프로필 = 기본 시퀀스) |

### 9-7. 용어집·UX 라이팅 원칙

**핵심 판단 — "자서전"이라는 말**: **부모 화면에서 쓰지 않는다.** "자서전"은 P1
문제("크고 막연한 일")를 화면 안에서 되살리는 말이다 — 부모에게 이것은 매일의
**이야기**여야 한다. 자녀 화면·랜딩에서는 "1년 뒤 한 권의 책"(구체물)을 쓰고,
"자서전"은 검색·광고 문맥(GROWTH 영역)에만 허용한다.

| 개념 | 부모 화면 | 자녀 화면·랜딩 | 쓰지 않는 말 |
|---|---|---|---|
| 산출물 | 이야기 | 이야기 / 1년 뒤 한 권의 책 | 자서전(화면 내)·회고록·데이터·콘텐츠 |
| 오늘의 단위 | 오늘의 질문 | 오늘의 질문 | 미션·과제·퀘스트 (앱테크 어휘 금지) |
| 답하는 행위 | **들려주다** (버튼: "눌러서 이야기해 주세요") | 어머니가 이야기를 **남기다** | 녹음하다(기술어)·답변 제출(사무어) |
| STT 결과물 | 글로 정리한 이야기 | 글로 정리된 이야기 | 변환 결과·전사본·텍스트 |
| STT 대기 | 밤사이 글로 정리해 드려요 | 🌙 밤사이 정리 중 | 처리 중·인식 중 |
| 자녀 반응 | 응원 | 응원을 보내다 | 좋아요·댓글·피드백 |
| 축적 표면 | 지난 이야기 | 모아보기 | 아카이브·히스토리·피드 |
| 원음 | 방금 하신 말씀 / 목소리 | 어머니 목소리 듣기 | 오디오 파일·원본 음성 |
| 스킵 (I8) | **이 이야기는 넘어갈게요** (동사: 넘어가다) | 노출 없음 (§9-4 P1 규칙 4) | 건너뛰기·패스·거절·거부 |
| 민감 주제 스위치 | 노출 없음 (자녀 설정) | **여쭙지 않을 이야기** | 금지 주제·차단·필터링 |
