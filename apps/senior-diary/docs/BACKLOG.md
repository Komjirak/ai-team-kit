## 1. 에픽 지도 (실구현 순서)

```
E0  실구현 준비 (환경·빌드 뼈대)      ─ P0, 다른 에픽의 토대
E1  실 데이터 백엔드 (Firebase)        ─ P0, 목 저장소 → 실서버
E2  음성 파이프라인 (녹음·STT·정리)    ─ P0, 원칙 3의 다리 · G4에 의존
E3  알림 (푸시)                        ─ P1, 루프(I4)·회수(I6)를 실제로 닫음
E4  인증·계정 수명                     ─ P1, R3·IA O-1 (부모 계정이 사라지면 사고)
E5  콘텐츠 (질문 뱅크 32→365)          ─ P1, 집필 — 개발 아님
E6  결제·구독                          ─ P2, 두 게이트 통과 후 (§3-4 O1)
E7  G1 스모크 (랜딩·사전예약)          ─ P0(검증 트랙), D2 대기
E8  품질·릴리즈 (QA·EAS·스토어)        ─ P1→P2, 비가역은 PO
```

에픽 간 의존: E1·E2·E3는 E0(빌드 뼈대) 위에서만 실동작한다. E2는 **G4 실측**(스파이크
잔여)이 닫혀야 스택이 확정된다. E7은 나머지와 병렬(제품과 별개 표면).

## 3. "지금 무엇부터" — 실구현 첫 슬라이스 (#7 방침)

#7이 정한 첫 슬라이스는 **부모 핵심 루프(P1→P2)를 실동작으로**다. 데모는 이미 되므로,
실구현 첫 슬라이스의 최소 묶음은 다음 순서다(전부 D2/D5/이름과 **독립**):

1. **S1.2 Firebase 프로비저닝(PO)** → S1.3 배선 → S1.4 seam 교체 — 실 데이터.
2. **S2.5 G4 실측**(병렬, AI Hub) → S2.4 실 STT — 원칙 3의 다리.
3. **S3.5 권한 문구·scheme 확정 → S0.2 dev 빌드**(RM/PO) → S2.2 실마이크 검증.
4. **S3.1→S3.2 푸시** — 루프(I4)를 실제로 닫음.
5. **E7 랜딩(병렬 트랙)** — D2 승인 나는 즉시 집행.

**첫 슬라이스에서 빼는 것(등가 축소 여유 없음 — PRD §3-2):** E6 결제 전체, S2.6 이름
교정 UI(위치 결정 후), S5.2 365 확장(베타는 32문항으로도 4주 측정 가능 — 확장은 병렬),
D8 놓친 하루(안 A 기본값 유지).
