## A. 플랫폼 선택 — 네이티브 앱 vs 웹앱(PWA)+알림톡

### A-0. BE 기술 사실 요약 (이 위에 사업 렌즈를 얹는다)

BE 스파이크(`SPIKE_REALTIME_STT_WEB §B`)의 하드 사실 3개:
1. **iOS 카카오톡 인앱 브라우저에서 `getUserMedia(audio)`가 깨진다**(iOS 15.1+ 문서화된 한계) →
   웹 녹음은 **외부 브라우저 강제 오픈**이 전제(시니어 마찰). [Apple Dev Forums #699479](https://developer.apple.com/forums/thread/699479)
2. **iOS 웹푸시는 "홈 화면 추가" 필수**(iOS 16.4+) → 매일 질문 푸시를 켜려면 시니어가 수동 설치.
   [MagicBell](https://www.magicbell.com/blog/pwa-ios-limitations-safari-support-complete-guide)
3. **알림톡 daily 발송 = 월 ~24만 원/1,000명(건당 8원) + "매일 질문" 템플릿 심사 `미확인`.**
   [omago](https://www.omago.ai/ko/blog/kakaotalk-message-pricing-logic)

BE 결론: **web+알림톡 주 채널 비권고, 알림톡은 V1.5 보조.** 나는 이 결론을 **부모측에 한해
사업성으로 지지**하되, 통짜로 "네이티브 단일"이 아니라 **표면을 사용자별로 가르는 비대칭**을 권고한다.

### A-1. 핵심 통찰 — 이 제품은 사용자가 둘이고, 둘의 최적 표면이 다르다

이 BM에서 **부모(사용자)와 자녀(구매자)는 다른 행동을 한다.** 표면을 하나로 강제할 이유가 없다.

| | 부모측 핵심 행동 | 자녀측 핵심 행동 |
|---|---|---|
| 무엇을 | **매일 녹음 + 매일 질문 알림** (습관 엔진) | **결제 · 읽기 · 응원 · 선물 보내기** |
| 기술 요건 | 마이크 녹음(안정), 매일 푸시(무료·확실) | 결제 UI, 읽기 뷰어, 링크 공유 |
| 디지털 리터러시 | 낮음 (5070, R3 설치 장벽) | 높음 (35~49, `BUSINESS_CASE §4-3`) |
| 네이티브가 필요한가 | **예** — 녹음·매일 푸시가 web(특히 iOS)에서 깨지거나 장벽(A-0) | **아니오** — 웹으로 충분, 오히려 유리(A-2) |

→ **"웹이 유리한 건 자녀측, 네이티브가 필요한 건 부모측"이라는 비대칭이 실재한다.**
BE가 규명한 web의 약점(녹음·푸시)은 **전부 부모측 행동**에 걸리고, 자녀측 행동(결제·읽기)에는
그 약점이 하나도 걸리지 않는다.

### A-2. 자녀측을 웹으로 두는 BM 근거 3가지 (BE 기술 판정에 없던 사업 렌즈)

**① 결제 수수료 — 이것이 가장 큰 레버.**
자녀 결제를 **앱 인앱결제(IAP)로 받으면 애플·구글이 15~30%**를 가져간다(구글은 2026년 연내
국내 20%로 인하 예정, 외부결제 시 추가 5% 면제). 반면 **웹 PG 결제는 ~3.5%**(`BUSINESS_CASE §6-A`
원가 가정). [머니투데이 2026-04](https://www.mt.co.kr/tech/2026/04/30/2026043012573061260) ·
[글로벌이코노믹 2026-03](https://www.g-enews.com/article/ICT/2026/03/202603051041296495c5fa75ef86_1)

- P1(연 69,000원) 1건당 수수료 차이 `추정 계산`: 앱 IAP 30% = 20,700원 vs 웹 PG 3.5% = 2,415원 →
  **건당 ~18,000원, 마진의 ~26%p 차이.** 구독형·저단가 상품일수록 이 격차가 공헌이익을 좌우한다.
- 애플은 "앱 안에서 파는 디지털 구독"에 IAP를 강제하므로, **결제를 웹(외부 브라우저·자녀 폰)에서
  일으키는 것**이 수수료를 피하는 정공법이다. 자녀는 디지털 리터러시가 높아 웹 결제 마찰이 낮다.
- ⚠️ **정책 리스크**: 애플·구글의 외부결제 유도(steering) 규정은 국가·시점별로 변동이 크다
  (한국 인앱결제강제방지법에도 양사가 외부결제에 ~26% 부과로 대응한 전례
  [Shippen 가이드](https://productengineer.info/camp/ko/shippen/biz/inapp-purchase-3-of-1-rule-korea)).
  "웹에서 결제받고 앱에서 링크로 유도"의 허용 범위는 **RM/법무 확인 사항**. 다만 **자녀가 처음부터
  웹으로 진입**(선물 랜딩 → 웹 결제)하면 앱 스티어링 규정 자체를 우회한다.

**② 선물 플로우 — 웹링크가 스토어보다 매끄럽다.**
이 제품은 "자녀가 부모에게 보내는 선물"이다. 선물의 자연 매개는 **카카오톡 공유 링크**다
(선물하기 이용 여성 85.9%·30~40대 70%+, `BUSINESS_CASE §4-3`). 웹 결제 페이지는
**링크 하나로 카톡에 흐르지만**, 앱 스토어 결제는 "스토어 이동 → 설치 → 로그인 → 결제"로
선물 동선이 끊긴다. **선물의 구매자 전환(G1)에 직접 유리한 쪽은 웹이다** `추정, G1 검증 대상`.

**③ 부모 설치 장벽(R3)은 네이티브라도 이미 완화됐다.**
"네이티브면 부모가 설치해야 한다"는 약점은, `SPIKE_MVP_TECH §B-1`의 **초대 링크 원터치
로그인**(자녀 결제 → 초대 링크 → 부모 폰에서 링크 한 번 = 익명 인증 로그인, 회원가입·비밀번호
없음, ONYU 방식)으로 절반 흡수된다. 즉 자녀는 웹에서 결제·선물하고, 그 결제가 만든 초대 링크로
부모의 네이티브 앱을 원터치 활성화한다 — **두 표면이 초대 링크로 이어진다.**

### A-3. 왜 "web 단일 주채널"은 사업적으로도 비권고인가 (BE 판정 지지)

BE의 기술 비권고를 **사업 렌즈로도 지지한다:**
- web 단일의 유일한 실이익은 "부모 스토어 설치 회피"인데, iOS에서 그 이익이 **녹음 파손(외부
  브라우저 강제) + 푸시 장벽(홈 화면 추가)**으로 상쇄된다(A-0). **습관 엔진(매일 녹음·매일 푸시)이
  가장 약한 표면에 얹히는 셈** — K2(부모 지속률) 리스크를 구조적으로 키운다.
- 알림톡을 매일 채널로 쓰면 **월 24만 원/1,000명의 순수 추가비용 + 템플릿 심사 미확인**(A-0-3).
  푸시(무료)로 되는 일을 유료로 하는 것이라, 공헌이익률(~65%, §6-A)을 갉는다.
- **단 반전 조건**: BE 미확인 항목 2개가 뒤집히면 web의 부모측 약점이 줄어 판정이 흔들린다 —
  (a) **안드로이드 카톡 인앱 `getUserMedia` 실동작**(미확인), (b) **"매일 질문" 알림톡 템플릿
  심사 통과**(미확인). 그래도 **iOS 녹음 파손은 문서화된 사실**이라, 안드로이드만 열려도 iOS
  사용자(5070 갤럭시 쏠림이 있으나 iOS도 상당)를 포기하지 않는 한 부모측 네이티브 필요는 남는다.

### A-4. 비교 축 종합표 (BM 관점)

| 축 | 부모=네이티브+자녀=웹 **(권고)** | 네이티브 단일 | web(PWA)+알림톡 단일 |
|---|---|---|---|
| 시니어 도달·온보딩(R3) | 부모 네이티브(초대 링크 원터치). 자녀 진입 마찰 0 | 부모·자녀 다 설치 — 자녀 전환 마찰 | iOS 녹음·푸시 장벽으로 부모측 최악 |
| 배포·업데이트 속도 | 자녀 웹=즉시 / 부모 앱=스토어 심사 | 둘 다 스토어 심사 | 즉시(심사 없음) |
| **결제 수수료** | **웹 PG ~3.5%** (마진 최대) | 앱 IAP 15~30% (마진 최소) | 웹 PG ~3.5% |
| 선물 플로우 | **카톡 링크로 매끄러움** | 스토어 경유로 끊김 | 링크 매끄러우나 부모 활성화가 약함 |
| 리텐션 표면(푸시·위젯) | 부모 앱=APNs/FCM 무료+위젯 가능 | 동일(최상) | iOS 푸시 홈추가 필수 / 알림톡 유료·심사 |
| 개발·운영비 | 앱(6~8주) + 자녀 웹(경량) `추정` | 앱 6~8주(`§B`) | 웹+외부브라우저+알림톡 = 비슷하거나 + |
| 확장(일본 §6-A) | 앱 재사용 + 웹 다국어. **알림톡 미의존 = LINE권 확장 쉬움** | 앱 재사용 | 알림톡=한국 전용, 일본은 LINE 재설계 |

### A-5. A 판정 — **비대칭 하이브리드 (권고 1안)**

**부모 = 네이티브 앱(녹음·매일 푸시·위젯) / 자녀 = 웹(선물 랜딩·결제·읽기·응원) / 둘을 초대 링크로 연결.
알림톡은 V1.5 이탈군 리마인드 보조(BE·`§B-3` 판정 계승).**

근거 3줄:
1. **약점의 소재가 다르다** — web의 기술 약점(녹음·푸시)은 전부 부모측, 자녀측엔 하나도 안 걸린다.
   그래서 표면을 가르면 각 사용자가 자기에게 최적인 표면을 쓴다(A-1).
2. **자녀를 웹으로 두는 것이 마진과 전환을 동시에 올린다** — 결제 수수료 ~3.5% vs 앱 15~30%,
   선물은 카톡 링크로 매끄럽게(A-2). 이건 BE 기술 판정에 없던 **순수 BM 이득**이다.
3. **습관 엔진은 가장 튼튼한 표면에** — 매일 녹음·매일 푸시가 제품의 리텐션 심장(K2)이고,
   그것이 안정적인 곳은 네이티브다(A-3). web 단일은 이 심장을 iOS에서 약한 표면에 얹는다.

**트레이드오프표 (권고안이 감수하는 것):**

| 감수하는 것 | 크기 | 완화 |
|---|---|---|
| 두 표면(앱+웹) 개발·QA | 중 — 단 자녀 웹은 결제·읽기 중심 경량 `추정` | 자녀 웹을 MVP에선 "결제+열람+응원"만으로 얇게. 뷰어 확장은 V1.x(아이디어3) |
| 결제 웹-앱 스티어링 정책 리스크 | 중 | 자녀를 **처음부터 웹 진입**으로 설계해 앱 스티어링 규정 우회. RM/법무 확인 |
| 부모 스토어 설치는 여전히 남음 | 소 | 초대 링크 원터치 로그인으로 절반 흡수(§B-1) |

**이것이 확인되면 판정이 흔들린다(정직하게):**
- 애플/구글이 "웹 결제 후 앱 활성화" 구조를 스티어링 위반으로 강하게 제재하면 → 자녀 웹 결제의
  수수료 이득이 위태(그래도 선물 플로우 이득은 남음). **RM/법무 선확인 필요.**
- BE 미확인 2건(안드로이드 인앱 녹음·알림톡 매일 심사)이 둘 다 열리고 **iOS 비중이 낮다고
  판명**되면 → web 단일의 부모측 약점이 줄어 "자녀·부모 모두 웹" 안이 재부상. 현재 근거로는
  iOS 녹음 파손(문서화)이 이 반전을 막는다.

## B. 아이디어3 가격 모델 — 디지털 상시 읽기 / 인쇄 별도

### B-0. 무엇을 묻나

`PRD_PROPOSALS.md 아이디어3`: "1년 뒤 서프라이즈"만으론 보상 지연이 길어 이탈(K4) 위험 →
**디지털은 상시 읽기(웹소설 뷰어)로 앞당기고, 물성 인쇄 책은 마일스톤/서프라이즈로.**
BM 지시: **디지털 상시 읽기 = 기본 유료 포함 / 오프라인 인쇄 = 별도 추가 구매.**

### B-1. 기존 가격안(§6-A)과의 정합 — 사실은 이미 이 구조다

`BUSINESS_CASE §6-A` 현행 3안:

| 안 | 구성 | 아이디어3와의 관계 |
|---|---|---|
| **P1** 연 69,000원 | 365 질문 + 음성 입력 + **디지털북** / 인쇄 양장본 49,000원 **업셀** | **이미 "디지털 포함 + 인쇄 별도"다.** 아이디어3은 새 가격이 아니라 **디지털의 성격을 "1년 뒤 완성본"에서 "상시 읽는 뷰어"로 재정의**하는 것 |
| **P2** 90일 39,000원 | 회차권(칠순 이벤트) → 연장 | 디지털 상시 읽기가 90일 체험의 가치를 앞당겨 연장 전환↑ 가능 `추정` |
| **P3** 연 129,000원 | **인쇄 1권 포함** + 음성 원본 QR | 인쇄를 묶은 프리미엄 — 아이디어3의 "인쇄 별도"와 공존(번들 vs 개별) |

→ **가격표를 바꿀 필요가 없다.** 아이디어3이 요구하는 건 **가격 재구성이 아니라 서사·기능의
재배치**다: 디지털(P1 포함)을 상시 뷰어로 격상하고, "서프라이즈" 정서를 **인쇄 add-on으로 이관**한다.

### B-2. 두 축을 분리하면 딜레마가 풀린다

아이디어3의 걱정(`PRD_PROPOSALS`)은 "상시 읽기가 **1년 서프라이즈 정서를 희석**한다"였다.
**서프라이즈를 인쇄로 옮기면 둘 다 얻는다:**

| | 디지털 상시 읽기 (P1 포함) | 인쇄 책 (별도 add-on) |
|---|---|---|
| 목적 | **리텐션** — 매주 쌓이는 걸 자녀가 본다(원칙1·2 강화) | **마일스톤·서프라이즈** — 정서의 절정 |
| 정서 | "책이 되어가는 중"(진행감) | "1년의 완성본이 도착"(서프라이즈 유지) |
| 매출 역할 | 결제 유지·완주 유도(K4 개선) | **업셀 마진** |
| 서프라이즈성 | 없음(상시) | **여기로 이관 → 정서 보존** |

→ `BUSINESS_CASE §0` 보도자료("1년 뒤 책이 도착")의 정서는 **인쇄 책이 그대로 계승**한다.
디지털 상시 읽기는 서프라이즈가 아니라 **리텐션 장치**로 성격이 분리되므로 충돌하지 않는다.

### B-3. 인쇄 add-on 마진 (기존 원가 재활용)

`BUSINESS_CASE §6-A` 원가 가정: **인쇄·배송 ~2만/권**, 판매가 49,000원.

- 건당 마진 `추정 계산`: 49,000 − 20,000(인쇄·배송) − 1,715(PG 3.5%) ≈ **27,285원 (마진율 ~56%)**.
  (§6-A는 인쇄 공헌이익을 대략 반영해 전체 ~65%로 잡았고, 이 개별 계산은 그 안에 정합.)
- **P3(인쇄 포함 129,000)와의 관계**: P3은 인쇄를 선구매 번들. add-on(P1+인쇄)은 완주 후 구매.
  둘은 **구매 시점이 다른 같은 상품** — P3은 "처음부터 책까지", add-on은 "쓰다 보니 책으로".

### B-4. 리텐션·완주율(K4)·서프라이즈 재정의가 매출에 미치는 영향 (3안)

핵심 변수는 두 개: **완주율**(상시 읽기가 올린다 `추정`)과 **인쇄 업셀 전환율**(상시 읽기가
올릴지 내릴지 불확실). §6-A 인쇄 업셀 전환(비관20%/현실30%/낙관35%)을 기준으로:

| 시나리오 | 상시 읽기의 완주율 효과 | 인쇄 업셀 전환 효과 | 순 매출 방향 |
|---|---|---|---|
| **비관** | 완주 소폭↑ | "이미 다 읽음 → 인쇄 굳이?" 전환 **↓** (35→25%) `추정` | 인쇄 매출 소폭↓, 구독 유지↑로 상쇄 — **≈중립** |
| **현실** | 완주 30→40%대 `추정` (보상 앞당김이 이탈↓) | 전환 유지(30%) — 상시 읽기가 애착을 키워 "책으로 남기고 싶다" | **완주 모수↑ × 전환 유지 = 인쇄 매출↑** |
| **낙관** | 완주 크게↑ + 환불(K4)↓ | 상시 읽기가 **인쇄 욕구를 자극**(전환 35→45%) `추정` | 구독 재구매↑ + 인쇄↑ = **상방** |

- **K4(완주율·환불) 개선이 가장 확실한 이득**: "1년 기다려야 첫 가치"라는 지연이 완주 전
   환불의 주원인인데(§2 K4), 상시 읽기는 **가치를 매주 인도**해 이 리스크를 정면으로 낮춘다.
- **불확실한 것은 인쇄 전환 방향**: "다 읽었으니 인쇄 불필요" vs "애착이 커져 소장 욕구" —
   **어느 쪽이 이기는지는 G2/베타에서만 판별**된다. 그래서 인쇄를 **완주 시점에 정서적으로
   제안**("1년의 이야기를 손에 잡히는 책으로")하는 카피·타이밍 설계가 전환의 레버다(GROWTH·PD).

### B-5. B 판정 — **가격표 유지, 서사 재배치 (제안)**

1. **디지털 상시 읽기 = P1에 포함**으로 명문화(새 요금 없음). 뷰어 완성형은 V1.x(`PRD_PROPOSALS`
   PM 권고와 정합 — MVP는 I5/C5·I9/C6 축소형).
2. **인쇄 책 = 별도 add-on(49,000)으로 유지**, "1년 서프라이즈" 정서를 여기로 이관.
   P3(인쇄 번들)은 병존.
3. **원칙4 재정의**("1년 뒤 책" → "디지털 상시 읽기 + 인쇄 마일스톤")는 **브랜드 서사 변경**이라
   BRAND·PM·PO 합의 사항 — 나는 **가격·마진 정합성만 판정**했고, 서사 확정은 PO(D5·원칙4).
