# QA 체크리스트 — 하루담(가칭) MVP

> 소유: QA. 소비자: ORCH(커밋 판정)·RM(릴리즈 게이트)·APP/BE(수정 입력).
> 원본 근거: `PRD.md §9`(화면·상태)·`§9-5`(접근성 수치)·`§4`(성공기준 G1·G2·G4) ·
> `IA.md §5`(상태 축) · `docs/HARNESS.md`(검증 게이트: 종료코드) ·
> `app/README.md`·`app/docs/BE_CONTRACT.md`(미검증 목록·실패 모드).
>
> **이 문서는 "무엇으로 확인했는가"의 기준이다.** 통과 주장은 검증되기 전까지 주장일 뿐이다.
> 각 항목에는 **통과 기준**과 **추적(어느 문서에서 왔나)**이 붙는다. 판정은 종료코드·
> 실기기 육안·로그 중 하나로 하고, "아마·됐을 것"은 통과로 쓰지 않는다(HARNESS 규칙).
>
> **검증 층위 3단**(항목마다 표기):
> - 🟢 **G(게이트)** — 종료코드로 자동 판정. 커밋 전 필수.
> - 🔵 **L(로직)** — 헤드리스/런타임 로그로 판정. ⚠️ 현재 자동화 미배선(§0 참조).
> - 🟠 **D(기기)** — 실기기(dev build) 육안. 시뮬레이터·export는 필요조건이지 충분조건 아님.
>   배포 전 게이트에서만 최종 판정.

## 0. 지금 이 문서를 쓰는 시점의 진실 (정직 표기)

QA가 이 킷의 규칙("실기기 확인이 최종이다 — typecheck·export·시뮬레이터는 필요조건이지
충분조건이 아니다")에 따라 **현재 무엇까지 검증됐는지**를 먼저 못 박는다.

| 층위 | 지금 상태 | 근거 |
|---|---|---|
| 🟢 종료코드 게이트 | ✅ `tsc --noEmit` 0 · `expo export` ios/android/web 0 (이 컨테이너에서) | README "무엇을 실제로 검증했나", HARNESS 3차 |
| 🔵 파이프라인 로직 | ⚠️ **"헤드리스 22/22 pass" 주장은 있으나 재실행 불가** — `package.json`에 test 스크립트 없음, 저장소에 `*.test.*`/헤드리스 러너 파일 없음. 일회성 실행의 결과만 문서에 남음 | `package.json` 확인 · `find` 결과 0건 |
| 🟠 실기기 런타임 | ❌ **전부 미검증** — 아래 §7 미검증 표 | README "미검증", BE_CONTRACT §5 |

**QA 판정(사후 한 단락):**
- ① 이걸 가능하게 한 것: 헤드리스 검증이 **커밋된 스크립트가 아니라 세션 내 일회 실행**이라,
  다음 세션이 "22/22"를 재현할 수 없다. 재현 불가한 초록불은 늑대소년이 된다.
- ② 막는 규칙 한 줄: **"회귀는 재실행 가능한 형태로만 초록불로 센다 — 커밋된 스크립트가
  없으면 그 통과는 없는 것이다."**
- ③ 넣을 곳: 이 문서 §5(회귀) + §6 커밋 전 게이트의 **선결 과제 R-0**. → APP/BE에
  헤드리스 러너 커밋 요청(ORCH 경유).

## 1. 기능 체크리스트 — 핵심 루프와 분기

핵심 루프(§3-1 I1~I9). 각 항목의 통과 기준은 **관찰 가능한 결과**로 쓴다.

### 1-1. 핵심 루프: 녹음 → 정리 → 읽기 → 응원 → 반영

- [ ] 🟠 **P1→P2 녹음 진입** — P1의 [눌러서 이야기해 주세요] 탭 시 P2 오버레이가 뜨고
  질문이 계속 보인다. **통과**: 질문 텍스트가 녹음 중 화면에 유지됨 (§9-4 P2 "말하다 잊지 않게")
- [ ] 🟠 **녹음 → 로컬 저장** — [다 했어요] → [오늘은 여기까지] 후 답변이 `organizing`
  상태로 저장. **통과**: 앱 재실행 후에도 답변 존재(§7 D-영속과 함께 검증) · 로그
  `daily.status==='answered'` (BE_CONTRACT §3)
- [ ] 🔵 **밤사이 정리(자동 5s)** — 답변 후 5초 뒤 자동으로 `done` 전이 + 정리본 생성.
  **통과**: P1 카드가 "밤사이 글로 정리해 드릴게요"→다음날 정리본으로, 로그 `nightly.run`
  (BE_CONTRACT §3·§4). ⚠️ 타이머 실동작은 🟠 기기 확인 필요(README 미검증)
- [ ] 🔵 **밤사이 정리(수동 데모 트리거)** — 점검 인덱스 → 데모 도구 → 🌙 지금 정리하기.
  **통과**: 정리 전 답변이 즉시 `done`으로. (`src/app/index.tsx:71`)
- [ ] 🟠 **자녀 읽기(C4)** — 정리 전이면 "🌙 정리 중"(원음만), 정리 후면 글+원음.
  **통과**: 두 상태가 데이터에 따라 갈림 (§9-4 C4 빈/정리완료 · IA §5-1)
- [ ] 🟠 **응원 전송(C4)** — 하트+한마디 → [보내기]. **통과**: 자녀가 쓴 문구가 시스템 가공
  없이 그대로 저장 (§9-7 화자 분리)
- [ ] 🟠 **부모 반영(P1)** — 자녀 응원이 P1 상단 배너(💛)로 도착. **통과**: 응원 전송 후
  P1에 배너 표시 = 루프 완성 (§9-4 P1 · IA §5-1 CHEERED · README 체험 4)
- [ ] 🔵 **원음 보존(R7)** — 정리본이 생겨도 원음 메타가 유지되고 재생 자리가 남는다.
  **통과**: C4·P2에 ▶ 원음 재생 진입 존재, 합성/복원 기능 부재 (§3-4 O4, BE_CONTRACT stt)

### 1-2. 질문 분기: 프로필 · 스킵 · 민감 주제

- [ ] 🟠 **프로필 룰 분기(I2)** — C1b에서 고향="서울" 입력 후 초대 → P1 오늘 질문이
  "처음 서울에 올라오던 날"→"어릴 적 살던 동네"로 치환. **통과**: 프로필 값에 따라
  배달 질문이 바뀜 (§9-4 C1b 분기 가시화 · README 체험 5 · `pipeline/branching`)
- [ ] 🟠 **분기 가시화(신뢰 장치)** — C1b 고향 선택 시 치환 예시 1건이 그 자리에서 노출.
  **통과**: 인라인 미리보기 텍스트 표시 (§9-4 C1b)
- [ ] 🟠 **스킵 즉시 치환(I8)** — P1 [이 이야기는 넘어갈게요] → 확인창 없이 대체 질문으로
  치환 + "그럴 수 있어요. 다른 이야기를…" 한 줄. **통과**: 같은 화면에서 질문 교체
  (§9-4 P1 규칙 1). ⚠️ 대체 질문은 응답률에 산입 안 됨(측정 오염 주의 §4)
- [ ] 🟠 **스킵 하루 1회 상한(I8)** — 대체 질문도 스킵하면 "오늘은 쉬어가도 돼요" 휴식
  상태 + 주 버튼 사라짐. **통과**: 2회째 스킵 후 주 버튼 비노출 (§9-4 P1 규칙 2)
- [ ] 🔵 **반복 스킵 자동 제외(I8, 내부 규칙)** — 임계값 넘은 주제가 시퀀스에서 조용히 제외.
  **통과**: 부모 문구에 제외 사실 **비노출**(통보 금지) + 시퀀스에만 반영 (§9-4 P1 규칙 3)
- [ ] 🟠 **스킵 자녀 미노출** — "어머니가 넘겼어요"류 표시가 자녀 화면에 **없다**.
  **통과**: C3·C4에 스킵 이벤트 표면 부재, 응답 여부(3/7)만 (§9-4 P1 규칙 4)
- [ ] 🟠 **민감 주제 스위치** — C1b "여쭙지 않을 이야기"(배우자·투병·돈) 끄면 해당 주제
  제외 + 챕터 대체. **통과**: 사별/이혼 선택 시 배우자 스위치를 자동으로 묻지 **않음**,
  챕터 대체는 룰이 조용히 처리 (§9-4 C1b · `pipeline/branching`·`book`)

### 1-3. 책 조립 · 진행감

- [ ] 🔵 **책 조립(챕터=목차)** — 답변이 시간순이 아니라 챕터 슬롯에 쌓임. **통과**:
  C6 목차가 §3-5 챕터 구조 반영, 대체된 장은 대체명으로 표시("빠진 장" 미노출)
  (§9-4 C6 B2 · `pipeline/book`)
- [ ] 🟠 **진행감(C5)** — "23번째 이야기 / 365" + 진행 바. **통과**: 진행 수치가 답변 수와
  일치, C5·C6 B4가 **같은 값**(단일 공급원) (§9-4 C5·C6 · 팀 규칙 8)
- [ ] 🟠 **책 미리보기 본문(C6)** — B3 펼침면이 **실제 정리본 데이터**(목업 텍스트 금지),
  정리 전 이야기는 펼침면에 넣지 않음. **통과**: done 답변만 본문에 등장 (§9-4 C6 B3)
- [ ] 🟠 **주문/결제 버튼 부재(C6)** — B0 샘플 라벨 노출 + 주문 버튼 **없음**(무결제 §3-0).
  **통과**: C6에 구매 CTA 부재 (§9-4 C6 B0 · 헤드라인-화면 모순 방지)

### 1-4. 온보딩: 초대 · 프로필

- [ ] 🟠 **자녀 신청 2단계(C1)** — C1a(관계 필수 3) → C1b(프로필 선택 5 + 민감 스위치).
  **통과**: C1b 전체 미입력도 유효(빈 프로필=기본 시퀀스) (§9-4 C1)
- [ ] 🟠 **초대 발송·대기(C2)** — 링크 생성 → 카카오/복사, 발송 후 **대기 상태가 본체**.
  **통과**: 미개봉 구간에 자녀는 C3로 못 넘어감 (§9-4 C2 · IA §5-2 SENT)
- [ ] 🟠 **부모 초대 진입(P0, 1회)** — 자녀 호칭·이름 표시 + [시작하기] 버튼 하나.
  **통과**: 회원가입·비밀번호·코드 입력 **없음**(링크=로그인) (§9-1 D2 · IA §1-2)
- [ ] 🟠 **활성화 전이** — P0 완료 시 자녀 C2→C3 전환. **통과**: 부모 활성화 이벤트로
  자녀 세계가 대기→홈 (IA §3-3 시스템 전이 · §5-2 OPENED)
- [ ] 🟠 **초대 만료 해결 경로** — 링크 만료 시 부모가 아니라 **자녀 쪽 재발급**으로 되돌림.
  **통과**: P0 오류가 자녀 재발급 버튼으로 연결 (§9-4 P0 오류 · BE_CONTRACT §5)

## 2. 화면·상태 체크리스트 — PRD §9 상태 5종

규칙: **로딩 · 빈 · 오류(원인 코드) · 권한 거부 · 오프라인** 5종을 화면별로 확인.
"해당 없음"으로 명세된 칸은 그 명세대로 부재가 맞는지 확인(빈칸 아님).
오류 문구에는 **원인 코드**가 붙어야 한다(팀 규칙 6 — 코드 없는 "실패했어요" 금지).

각 화면 공통 통과 기준: 해당 상태를 유발했을 때 **§9-4 명세의 문구·원인 코드가 그대로**
표시되고, 앱이 죽지 않는다.

### G1 — 랜딩 (§9-2)
- [ ] 🟠 로딩: 정적 1장(폰트 로딩 중 시스템 폴백) — 스피너 없음
- [ ] 🟠 빈: 해당 없음(부재 확인)
- [ ] 🟠 오류: 폼 제출 실패 `reserve.submit_failed` + 입력값 보존
- [ ] 🟠 중복 제출: "이미 신청된 연락처예요"
- [ ] 🟠 오프라인: `reserve.submit_failed (offline)`
- [ ] 🟠 가격·출시일 **미표기** 확인 (§5-1 🔒)

### P0 — 초대 진입 (§9-4 P0)
- [ ] 🟠 로딩: 문장만("초대장을 확인하고 있어요"), **스피너 금지**, 1초 내
- [ ] 🟠 오류: `invite.link_expired` — 자녀에게 재발급 되돌림
- [ ] 🟠 권한 거부: 해당 없음(이 화면 권한 요청 없음) 확인
- [ ] 🟠 오프라인: `invite.verify_failed (offline)`

### P1 — 오늘 (§9-4 P1)
- [ ] 🟠 로딩: 이전 화면 유지 + "오늘 질문을 가져오고 있어요", 전체 스피너 금지
- [ ] 🟠 빈: 첫날(답변 0) 지난 이야기 링크 **숨김**
- [ ] 🟠 오류: `question.fetch_failed` + [다시 시도]가 주 행동 자리
- [ ] 🟠 권한 거부: 알림 거부해도 앱 무제한 + "알림을 켜면…" 1줄, 강요 배너 금지
- [ ] 🟠 오프라인: 마지막 질문 표시 + **오프라인에도 녹음 가능** 안내

### P2 — 녹음 (§9-4 P2)
- [ ] 🟠 로딩: 해당 없음(로컬 녹음, 시작 지연 없음)
- [ ] 🟠 빈: 3초 미만 녹음 시 "짧게 담겼어요. 이대로 보낼까요?" (실수 탭 방어)
- [ ] 🟠 오류: 업로드 실패 시 **유실 없음을 먼저** — `answer.upload_failed (offline)` /
  서버 `answer.upload_failed (server)` + 자동 재시도
- [ ] 🟠 권한 거부: `record.mic_denied` + [허락하러 가기] + **[글로 쓸게요] 대안**(I3)
- [ ] 🟠 오프라인: 녹음·로컬 저장 정상 + "연결되면 자동으로 보내드려요"

### P3 — 지난 이야기 (§9-4 P3)
- [ ] 🟠 로딩: 이전 목록 유지 + "새 이야기를 확인하고 있어요"
- [ ] 🟠 빈: "첫 이야기를 남기면 여기에…" + [오늘 질문으로 가기]
- [ ] 🟠 오류: `archive.fetch_failed` + [다시 시도]
- [ ] 🟠 권한 거부: 해당 없음
- [ ] 🟠 오프라인: 캐시 목록 + "연결되면 최신 이야기를…"

### C1 — 신청·프로필 (§9-4 C1)
- [ ] 🟠 로딩: 제출 중 버튼 비활성 + "만드는 중…"
- [ ] 🟠 빈: C1b 전체 미입력 유효 + "나중에 채워도 돼요"
- [ ] 🟠 오류: `signup.submit_failed` + 입력값 보존(C1a·C1b 모두)
- [ ] 🟠 오프라인: `signup.submit_failed (offline)`, C1a→C1b 이동은 로컬이라 정상

### C2 — 초대 보내기·대기 (§9-4 C2)
- [ ] 🟠 로딩: "초대장을 만들고 있어요"
- [ ] 🟠 빈: 해당 없음(대기 상태가 정상)
- [ ] 🟠 오류: `invite.create_failed` + [다시 시도]
- [ ] 🟠 오프라인: [카카오톡으로 보내기] 비활성 + 안내

### C3 — 홈 (§9-4 C3)
- [ ] 🟠 로딩: 스켈레톤 카드
- [ ] 🟠 빈: 활성화 전 C2 대기로 대체 / 활성화 후 0건 "첫 이야기를 기다리고 있어요"
- [ ] 🟠 오류: `feed.fetch_failed` + [다시 시도]

## 3. 접근성 체크리스트 — 시니어(§9-5)

### 3-1. 부모 화면 (P0~P3) — 엄격 기준
- [ ] 🟠 **본문 최소 20pt** / 질문·이야기 본문 **28pt+** / 버튼 라벨 22pt (§9-5)

- [ ] 🟠 **OS 글자 200%까지 레이아웃 파손 없음** — 스크롤 흡수, **말줄임 금지**
