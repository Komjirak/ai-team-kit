## 0. 요약 (한 문단)

date.log는 **커플이 함께 갈 곳을 담고, 다녀온 곳으로 넘기고, 그 궤적을 지도·숫자로
되돌아보는** 2인용 장소 기록 서비스다. 이번 작업은 새 기능을 얹는 프로젝트가 아니라
**이미 검증된 흐름(담기 → 다녀오기 → 코스 → 돌아보기)을 그대로 두고, 반응형 웹으로
다시 짓고 시각적으로 리터칭**하는 일이다. 핵심 가치 세 가지 — ①커플 페어링(초대코드),
②장소 위시리스트↔방문 전환, ③지도 위 데이트 코스 — 를 흔들지 않는다. 게이미피케이션
(함께한 날수·등록 수 경쟁)은 이 궤적을 **감정적으로 보상**하는 장치로 유지하되, 압박이
아니라 회고가 되도록 문구·강도를 다시 잡는다. V1은 웹 단일, 계정은 기존 로그인 방식을
승계한다.

## 1. 문제 정의 · 리터칭의 이유

### 1-1. 왜 다시 짓는가 (기능이 아니라 그릇의 문제)

기존 date.log는 흐름 자체는 성립한다. 리터칭이 푸는 것은 **기능 부족이 아니라
그릇·일관성·반응형 부재**다.

| # | 문제 | 지금 | 리터칭이 노리는 것 |
|---|---|---|---|
| P1 | **반응형 미흡** | 데스크톱 중앙정렬 레이아웃 위주. 모바일에서 카드·지도·필터칩이 최적화되지 않음 | 커플이 실제로 쓰는 순간은 **밖에서, 폰으로**다. 모바일 우선 반응형이 1순위 |
| P2 | **비주얼 일관성** | 뱃지·버튼(코랄/에스프레소/핑크)·여백이 화면마다 제각각으로 읽힘 | 하나의 디자인 시스템(토큰·컴포넌트)으로 통일 |
| P3 | **첫 진입 공허** | 관계 시작일·장소가 없으면 "우리의 기록"이 0으로 비어 동기 부여가 약함 | 빈 상태(empty state)를 **다음 행동으로 잇는 안내**로 재설계 |
| P4 | **게이미피케이션의 톤** | "누가 더 많이 등록했을까" 등 경쟁 요소가 자칫 압박이 될 수 있음 | 경쟁을 **함께 쌓는 회고**로 톤 조정 (§9 라이팅 원칙) |

### 1-2. 우리가 하지 않을 싸움 (리터칭 경계)

- **정보구조를 새로 발명하지 않는다.** 필터 5탭(전체/가고싶은 곳/데이트코스/추억/우리의
  기록)과 담기→방문 전환 흐름은 **검증된 자산**이다. 재배치는 하되 갈아엎지 않는다.
- **네이티브 앱으로 확장하지 않는다.** V1은 반응형 웹 단일 (§3 뺄 것 X-앱).
- **소셜·공개 피드로 넓히지 않는다.** date.log는 **한 커플의 사적 공간**이다.

## 2. 타깃 · 사용 맥락

### 2-1. 타깃

| | 세그먼트 | V1 우선순위 | 왜 |
|---|---|---|---|
| **S1** | **20~30대 커플, 데이트를 "찾고·기록"하는 층.** 인스타 저장·카톡 링크로 갈 곳을 모아두지만 흩어져 있음 | **주 타깃** | date.log의 위시리스트가 그 "흩어진 저장"을 **둘이 함께** 모으는 자리를 대체한다 |
| **S2** | **기념일·N일차를 챙기는 커플** | 부 타깃 | 함께한 날수·첫 기록이 이 층의 감정 훅 |
| **S3** | 오래된 커플/부부 | 배제하지 않음 | 회고(지도·통계) 가치가 이들에게 더 큼. 단 V1 카피는 S1 기준 |

### 2-2. 사용 맥락

| | 맥락 A — 계획할 때 | 맥락 B — 다녀온 뒤 |
|---|---|---|
| 언제 | 데이트 전, 침대/지하철에서 "어디 갈까" | 집에 와서 "오늘 거기 좋았지" |
| 기기 | **모바일 우선** | 모바일 + 가끔 데스크톱(코스 정리) |
| 핵심 행동 | 장소 담기 · 코스 짜기 · 길찾기 | 다녀왔어요 전환 · 추억/사진 남기기 |
| 설계 요구 | 검색·담기 **탭 최소** | 전환 1탭, 사진 업로드 쉬움 |

**세션 상한 의식:** 데이트 계획은 짧게 여러 번, 회고는 가끔 길게. 두 리듬 모두
**모바일에서 엄지 하나로** 끝나야 한다.

## 4. 정보구조(IA) · 반응형 내비게이션

```
[헤더] date.log 로고 · 슬로건 | 알림벨 | 사용자칩(닉네임·파트너 초대 ▼)
[필터바] 전체 · 가고싶은 곳 · 데이트코스 · 추억 · 우리의 기록   ← 5탭(칩)
─────────────────────────────────────────────
본문 = 선택된 탭의 콘텐츠
```

| 브레이크포인트 | 필터바 | 본문 그리드 | 헤더 |
|---|---|---|---|
| **모바일 <640px** | 가로 스크롤 칩 (또는 하단 고정 탭바 §10-A) | 1열 카드, 지도 풀블리드 | 로고 축약 + 벨 + 아바타 |
| **태블릿 640–1024** | 상단 칩 유지 | 2열 카드 | 전체 표시 |
| **데스크톱 >1024** | 상단 칩 유지, 콘텐츠 max-width ~1120px 중앙 | 3열 카드, 지도 넓게 | 전체 표시 |

**규칙:** 5탭 라벨·순서·선택 상태(코랄 필)를 세 브레이크포인트에서 동일하게 유지한다.
데스크톱에서만 보이는 기능/모바일에서만 보이는 기능을 만들지 않는다(반응형 = 재배치,
기능 동등).

## 5. 화면 흐름 + 텍스트 와이어프레임 + 상태 명세

> **오류·빈·로딩 상태를 명세하지 않은 화면은 미완성이다.** 각 화면에 로딩 · 빈 ·
> 오류 · 오프라인/지도실패 상태를 적는다. 해당 없으면 "해당 없음"이라 **적는다.**

### 5-0. 전체 흐름

```
[최초] 로그인 ─► (커플 미결합) 온보딩: 초대코드 만들기 / 코드로 합류하기 ─┐
                                                                        ▼
[상시]  홈(전체) ─┬─ 가고싶은 곳 ─ 장소상세 ─[다녀왔어요]─► 다녀온 곳
                 ├─ 데이트코스 목록 ─ 코스상세(지도·순서·길찾기)
                 ├─ 추억 ─ 추억상세(사진·후기)
                 └─ 우리의 기록(대시보드)
        헤더 ─ 설정(초대코드·관계시작일·계정) / 알림
[담기]  장소 추가(검색→선택→카테고리·메모) ─► 위시리스트
[코스]  코스 만들기(장소 다중선택→순서→저장)
```

### 5-1. 온보딩 · 커플 결합

```
┌────────────────────────────────┐
│  date.log                      │
│  우리가 함께 걸은 곳            │
│                                │
│  ┌──────────────────────────┐  │
│  │   내 초대코드 만들기      │  │  ← 코드 발급 → 공유 시트
│  └──────────────────────────┘  │
│  ┌──────────────────────────┐  │
│  │   초대코드로 합류하기     │  │  ← 6자리 입력
│  └──────────────────────────┘  │
│  파트너가 합류하면 같은 커플로  │
│  연결돼요.                     │
└────────────────────────────────┘
```

| 상태 | 명세 |
|---|---|
| 로딩 | 코드 발급 중 버튼 스피너 |
| 빈 | 해당 없음 |
| 오류 — 코드 무효/만료 | `초대코드를 확인해 주세요. (invite.invalid)` 인풋 하단 표시 |
| 오류 — 이미 다른 커플 결합됨 | `이미 연결된 계정입니다. (couple.already_bound)` + 설정 안내 (C1) |
| 오프라인 | `연결이 필요합니다.` 재시도 버튼 |

### 5-2. 홈 — 전체 / 가고 싶은 곳 (리스트·그리드)

```
[가고 싶은 곳]                      [가고 싶은 곳 추가]
위시리스트 3곳
┌───────────┐ ┌───────────┐ ┌───────────┐
│ [카테고리]│ │ [카테고리]│ │ [카테고리]│  ← 뱃지
│  썸네일    │ │  썸네일    │ │  썸네일    │
│  장소명    │ │  장소명    │ │  장소명    │
│  주소      │ │  주소      │ │  주소      │
│ [다녀왔어요] 수정·삭제 → ...              │
└───────────┘ └───────────┘ └───────────┘
전환한 장소는 "다녀온 곳" 목록에서 볼 수 있어요.
```

| 상태 | 명세 |
|---|---|
| 로딩 | 카드 스켈레톤 3~6개 |
| **빈 — 위시리스트 0** | "아직 담은 곳이 없어요. 가고 싶은 곳을 담아보세요. [가고 싶은 곳 추가]" — **빈 화면을 다음 행동으로 연결** (P3) |
| 오류 | `목록을 불러오지 못했어요. (place.list_failed)` + [다시 시도] |
| 오프라인 | 캐시 있으면 표시(썸네일 회색), 없으면 오류와 동일 |
| 전환("다녀왔어요") | 낙관적 업데이트로 카드가 "다녀온 곳"으로 이동 + 되돌리기 토스트(5초) — **단방향이 기본이나 실수 복구 여지** (C4) |

### 5-3. 장소 추가

```
┌────────────────────────────────┐
│ ✕  가고 싶은 곳 추가            │
│  ┌──────────────────────────┐  │
│  │ 🔍 장소 검색             │  │  ← 지도 SDK 검색 (§10-B)
│  └──────────────────────────┘  │
│  선택: 한남작업실 / 이태원로55나길 7 │
│  카테고리  [카페][맛집][기타…]  │
│  메모(선택) ______________      │
│           [ 담기 ]             │
└────────────────────────────────┘
```

| 상태 | 명세 |
|---|---|
| 로딩 | 검색 중 인라인 스피너 |
| 빈 | 검색 0건: "검색 결과가 없어요. 다른 이름으로 찾아보세요." |
| 오류 — 검색 실패 | `장소 검색에 실패했어요. (search.failed)` — 직접 입력 폴백 제공 |
| 오류 — 저장 실패 | `담지 못했어요. (place.save_failed)` + 재시도, 입력 유지 |
| 오프라인 | 검색 비활성 + 안내. 직접 입력만 허용 |

### 5-4. 데이트 코스 상세

```
← 코스 목록                        수정  삭제
┌────────────────────────────────┐
│  한남동                     ⤴   │  ← 이름·메모·장소 수·공유
│  장소 3곳                       │
├────────────────────────────────┤
│  [ 지도 — 순서대로 핀 연결 동선 ]│
├────────────────────────────────┤
│  코스 순서                      │
│  ① 한남작업실 [카페][위시리스트] │
│     주소                        │
│     ↓ 직선거리 0.17km·도보 3분 [길찾기]
│  ② 현대카드 뮤직 라이브러리      │
│     ↓ 0.32km·도보 5분 [길찾기]  │
│  ③ 사운즈 한남                  │
└────────────────────────────────┘
```

| 상태 | 명세 |
|---|---|
| 로딩 | 지도 자리 스켈레톤, 리스트 먼저 |
| 빈 — 장소 0/1 | 코스는 2곳 이상 권장. 1곳이면 지도만·동선 없음 + "장소를 더 담아 코스를 이어보세요" |
| **오류 — 지도 SDK 실패** | 지도 자리에 `지도를 불러오지 못했어요. (map.load_failed)` + [다시 시도] — **리스트·거리·길찾기 링크는 그대로 동작** (지도 없어도 코스 성립) |
| 오류 — 길찾기 딥링크 실패 | 토스트 안내, 좌표 복사 폴백 |
| 오프라인 | 지도 실패 상태와 동일, 저장된 순서·주소는 표시 |

### 5-5. 우리의 기록 (대시보드 · 게이미피케이션)

```
우리의 기록 — 숫자로 돌아보는 우리
┌────────────────────────────────┐
│ 함께한 지                       │
│ 관계 시작일을 설정해주세요       │  ← 미설정 시
│ [ 설정에서 입력하기 → ]         │
└────────────────────────────────┘
[ 1 다녀온 곳 ][ 3 가고싶은 곳 ][ 0 남긴 추억 ][ 0 사진 ]
┌ 추억이 가장 많은 곳 ┐ ┌ 우리의 첫 기록 ┐
│ 아직 없어요         │ │ 삼성대주옥 2026.08.31 │
└─────────────────────┘ └─────────────────┘
누가 더 많이 등록했을까 🏃
러너를 누르면 그 사람이 등록한 목록을 볼 수 있어요
[ ───────🏃──────────────🏁 ]  은애 · 4곳
```

| 상태 | 명세 |
|---|---|
| 로딩 | 통계 카드 스켈레톤 |
| **빈 — 관계 시작일 미설정** | "함께한 지" 카드가 [설정에서 입력하기 →]로 연결 (P3) |
| 빈 — 통계 0 | 숫자 0 그대로 + 각 카드가 해당 탭으로 이동(다녀온 곳 0 → "첫 장소를 담아보세요") |
| 빈 — 파트너 미합류 | 등록 수 비교는 **본인만 표시**하고 "파트너가 합류하면 함께 겨뤄봐요"로 유도 |
| 오류 | `기록을 불러오지 못했어요. (stats.failed)` + [다시 시도] |


| 상태 | 명세 |
|---|---|
| 로딩 | 없음(로컬/캐시) |

| 오류 — 시작일 저장 실패 | 값 롤백 + `저장하지 못했어요. (settings.save_failed)` |
| 오류 — 코드 복사 실패 | 폴백: 코드 텍스트 선택 가능하게 |
| 오프라인 | 표시는 정상, 저장은 재시도 |
