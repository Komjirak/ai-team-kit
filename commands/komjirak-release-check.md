릴리즈 게이트를 실행한다. RM 하네스(`${CLAUDE_PLUGIN_ROOT}/agents/komjirak-release.md`)와
`${CLAUDE_PLUGIN_ROOT}/docs/PLAYBOOKS/OTA_AND_BUILDS.md`를 기준으로 다음을 점검하고,
항목별 통과/실패/해당없음을 표로 보고하라:

## 코드 게이트
- [ ] verify 통과 (종료코드 판정)
- [ ] 번들 검증 (양 플랫폼 export)
- [ ] 트리 클린 + 원격 동기화 (`git status`, origin과 diff 없음)
- [ ] 번들 태그(커밋 7자)로 배포물 식별 가능

## 경로 판정
- [ ] 이 변경은 OTA로 가능한가? (OTA 불가 목록 대조 — 네이티브 모듈·권한 문구·
      네이티브 설정값·버전)
- [ ] 빌드가 필요하면: 남은 빌드 예산, dependencies가 대상 바이너리와 동일한지
- [ ] 플랫폼 플래그 명시 — 같은 runtime의 다른 플랫폼에 영향 없는지

## 스토어·콘솔 게이트 (제출/출시일 때)
- [ ] 지급 계약·상품 승인 상태
- [ ] 개인정보 라벨이 실제 수집 항목과 일치
- [ ] 인증 콘솔 스위치 (익명 로그인 켜짐, 자동 정리 꺼짐 등)
- [ ] 권한 문구에 placeholder 없음
- [ ] 스크린샷이 실제 화면이고 헤드라인과 모순 없음

## 최종
- [ ] 실기기 확인 계획 (누가·어떤 신호로 — 번들 태그, 오류 코드)
- [ ] **PO 승인** — 버튼은 PO가 누른다

전 항목 판정 후: 실패 항목이 있으면 릴리즈 불가로 보고하고 해결 순서를 제안한다.
통과면 PO에게 승인 요청 사항을 한 줄 명령 단위로 정리해 전달한다.
