# 플레이북 — 앱 스토어 심사 대응

채록 iOS 1.0.0의 실전 기록(제출 4번, 반려 3번, 8일)에서 뽑은 절차다.
반려는 **자동 심사 → 사람 심사 → 정책 심사** 순으로 깊어진다 — 층마다 보는 것이
다르므로 대응도 다르다.

## 제출 전에 막을 수 있는 것 (자동 심사 층)

- **안 쓰는 권한은 키 자체를 제거한다.** 플러그인이 기본 문구(placeholder)를
  Info.plist에 박아두면, 해당 기능 코드가 한 줄도 없어도 기계가 거절한다.
  (채록: expo-image-picker의 microphonePermission 기본 문구로 1차 반려)
- 쓰는 권한 문구에는 **용도 + 구체적 예시**를 넣는다.
- 권한 문구 반영처는 여러 곳이다 (플러그인 옵션 + 로케일 파일) — 세트로 고친다.

## 사람 심사 층

- **심사관은 비주류 기기를 쓴다.** iPad 등에서 전 화면을 열어본다 — 전폭 레이아웃,
  탭바, 오류 안전망을 전수 점검하고 제출한다. (채록: iPad Air 5에서 오류 화면 → 2.1 반려)
- **스크린샷은 실제 앱 화면이어야 한다.** 그라데이션+목업 합성은 promotional 판정.
  헤드라인과 화면 내용이 모순되면 안 된다. (채록: 2.3.3 반려, 24장 재작업)
- 반려문에 "오류 스크린샷을 못 찾았다"면 다음 제출에 **캡처를 달라는 요청을 동봉**한다.

## 정책 심사 층

- **계정 기반이 아닌 IAP에 개인정보 등록을 강제하지 말라(5.1.1(v))** — 결제 전에
  로그인 시트를 띄우면 걸린다. 채록의 해법: **익명 인증으로 결제 → 로그인은 결제
  뒤 선택 유도.** (상세: PAYMENTS_IAP.md)
- 반려문이 우리 반박 논리까지 미리 막아놨으면 항고보다 수정이 빠르다.
- Resolution Center 회신은 구조를 재사용한다: 지적 사항 → 원인 → 조치 → 확인 방법.

## 반려 대응 순서 (불변)

```
원인을 재서 확정한다 (추측 금지)
 → 고친다 → verify → (필요 시에만) 빌드 → 회신
```

빌드 예산이 유한하므로 추측 수정으로 빌드를 태우지 않는다. Info.plist 등
네이티브 값은 OTA로 못 고친다 — 재빌드 항목인지 먼저 판정한다.

## 출시 당일 기대치 (오판 방지)

- 릴리즈 직후 스토어 링크 404는 정상. 전파는 순차다 (채록: 미국 +20분, 한국 +35분).
- **IAP 상품 메타데이터는 앱 목록보다 훨씬 늦다** (채록: 하룻밤 ~11시간).
  그동안 페이월이 폴백(비활성)으로 뜨는 것은 설계된 안전 강등이다 — 장애가 아니다.
- 첫 실행은 내장 번들로 돈다 (OTA는 2회차) — 낡은 상태가 보여도 당황하지 않는다.
- 옵트아웃하지 않으면 iPhone 앱이 Apple Silicon Mac App Store에도 노출된다 — 사전에 결정한다.

## 테스터 트랙 요건 (Android)

- 프로덕션 액세스 요건("최근 N일 연속 M명")은 누적이 아니다 — **이탈 한 명이
  카운트를 깬다.** 테스터는 정원이 아니라 버퍼(요건+2~3명)로 운영한다.
- 판정은 콘솔의 요건 카드 표시로만 한다 — 추정하지 않는다.
- 내부 테스트 트랙은 카운트와 무관하다 — 검증용으로 자유롭게 쓴다.
