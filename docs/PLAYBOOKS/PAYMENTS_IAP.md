# 플레이북 — 인앱결제·구독 파이프

채록의 결제 사고 시리즈(첫 OTA가 드러낸 구독 사고 3연속 + 웹훅 순서 사고)에서
확정된 모델이다. 스택은 스토어 IAP → RevenueCat류 SDK → 웹훅 → DB(등급) 기준.

## 파이프 전체 그림

```
스토어 결제 → 결제 SDK (app_user_id) → 웹훅 → DB users/{uid}.tier → 앱·웹·익스텐션 등급
```

전 구간이 실거래로 검증되기 전까지는 "결제 붙었다"고 말하지 않는다. 검증의 끝은
서버 로그의 구조화 이벤트 한 줄(`{"type":"INITIAL_PURCHASE","outcome":"applied",...}`)과
모든 표면(앱·웹·익스텐션)의 등급 일치다.

## 정체성 모델 (사고 3연속의 결론)

1. **결제 SDK의 app_user_id는 정체(identity)다.** 인증 uid와 1:1로 맞춘다 —
   결제 전에 `identifyPurchaser`(uid 연결)부터.
2. **영수증 제출은 조회가 아니라 소유권 이전이다.** 복원·재제출이 다른 uid에서
   일어나면 구독이 그 uid로 이관된다(TRANSFER). "확인만 해보자"로 제출하면 안 된다.
3. **판단 로직은 순수 함수로 분리하고 규칙표 검증에 넣는다.** 채록은 정체 판단을
   `purchaserIdentity.ts`로 빼서 verify 규칙표 수백 건으로 박제했다 — 사고마다
   규칙이 표에 추가된다.
4. **낡은 uid 신호를 가드한다** (seenUid 가드) — 로그아웃·계정 전환 직후의 이벤트가
   이전 계정의 등급을 덮지 않게.
5. **로그아웃 후 복원 재발화를 차단하고, 스토어/캐시 신호는 무해화한다.**

## 웹훅 규칙

- **웹훅은 순서를 보장하지 않는다.** 몇 초 간격의 이벤트 두 건이 뒤집혀 도착할 수
  있다 — "마지막 도착이 이긴다"로 쓰면 이관 직후 free로 굳는 사고가 난다.
  **이벤트 시각 가드**(`writeTierIfNewer` + `tierEventAt` 도장)로 낡은 이벤트를 거른다.
- 수동 부여(운영자 grant)에도 같은 도장을 찍는다 — 안 찍으면 웹훅이 되덮는다.
- 부여 경로는 하나로 일원화한다 (대시보드 부여 vs 스크립트 부여가 섞이면 반쪽 상태가 생긴다).

## 익명 인증 결제 (정책 심사 대응)

- 결제 전에 로그인을 강제하면 iOS 5.1.1(v)에 걸린다. 구조: **익명 세션으로 결제 →
  로그인은 결제 뒤 선택 유도** (여러 지점에서 부드럽게).
- **코드에 signInAnonymously를 넣으면 콘솔 스위치가 세트다** — 익명 인증은 기본값
  꺼짐이고, 꺼진 채면 `ADMIN_ONLY_OPERATION`이 나는데 앱에는 모호한 안내만 보인다.
- **비활성 익명 계정 자동 삭제(30일)를 끈다** — 켜져 있으면 한 달간 앱을 안 연
  익명 구독자의 uid가 사라져 등급 조회가 끊긴다. 이것이 "계정 연결" 배너를 계속
  띄워야 하는 실질적 이유다.
- 익명 → 정식 계정 연결 시 구독 이관 경로를 별도로 검증한다.

## 검증·운영 체크리스트

- [ ] 페이월 폴백: 상품 로드 실패 시 안전 강등(폴백 가격 + 비활성 버튼)이 설계돼 있다
- [ ] 등급 검사(보안 규칙 포함)는 서버 등급이 진실 — 앱 배지는 캐시일 수 있다
      (앱 PRO인데 서버 free면 permission-denied — 배너의 오류 코드로 판별)
- [ ] 무료 체험 중 매출 $0은 정상 — 첫 실청구는 체험 전환일
- [ ] 테스트 검증은 **깨끗한 Free에서 시작한다** — 서버 등급 회수 + SDK 고객
      (샌드박스 잔재) 삭제 후 실계정 결제로 전 구간 확인
- [ ] 지급 계약·세금·은행 + 상품 승인 상태는 릴리즈 게이트 항목이다
